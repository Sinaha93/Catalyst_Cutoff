# Catalyst_Cutoff

Windows PC에서 혼자 사용하는 촉매 마감 자동화 프로그램입니다. 최종 목표는 ERP·희성·유미코아 자료를 대조하고, 제품별 물류 흐름과 BOM으로 마감 수량을 검토한 뒤 엑셀을 생성하는 것입니다. **현재 W1 실행·저장 기반을 구현했습니다. 월 작업 생성·메모 자동 저장·재실행 복원을 지원하며 자료 읽기·마감 계산·확정·출력은 아직 구현 전입니다.**

## 실행 및 검증

Windows, Python 3.12 이상, Node.js 22.12 이상을 사용합니다. 검증 환경은 Python 3.12.14 / Node 24.15.0 / Microsoft Edge입니다. Python과 npm 의존성은 `requirements.txt`와 `frontend/package-lock.json`에 고정했습니다. 현재 개발 실행본이며 단독 EXE 배포는 W7 범위입니다.

```powershell
# 최초 설치 (실제 python.exe 경로를 지정할 수도 있습니다)
.\setup.ps1 -PythonPath 'python'

# 실행: 처음 한 번 업무 자료를 보관할 폴더를 선택합니다.
.\start.ps1

# 기존 폴더를 명시해서 실행하거나, 선택한 폴더를 바꿀 때
.\start.ps1 -DataDir 'D:\촉매 마감 자료'
.\start.ps1 -ChooseDataDir
```

설치 후에는 `Run.cmd`를 더블 클릭해도 실행할 수 있습니다.

업무 자료는 코드 저장소 밖에 보관합니다. 기본 실행에서 선택한 폴더는 `%LOCALAPPDATA%\CatalystCutoff\settings.json`에 기억하며, 명시적인 `-DataDir` 실행은 기본 선택을 바꾸지 않습니다. 프로그램은 사용 가능한 로컬 포트를 배정하고 브라우저를 엽니다. 화면의 ‘프로그램 종료’로 서비스를 종료합니다. 브라우저 탭만 닫아도 서비스가 종료되는 것은 아닙니다. 미저장 입력이 있으면 종료 전에 저장합니다. 같은 자료 폴더의 두 번째 서비스 실행은 차단합니다.

```powershell
.venv\Scripts\python.exe -m pytest -q
Set-Location frontend
npm.cmd run build
npm.cmd run test:browser
```

브라우저 검증은 설치된 Edge를 사용하고 임시 자료 폴더에서 실행합니다. 실 업무 원본은 읽거나 변경하지 않습니다. 검증 범위와 제한은 [W1 구현 기록](docs/reviews/2026-10-13-W1-구현검증.md)을 참고합니다.

## 현재 진행 단계 — 2026-10-13

**W1 실행·저장 기반을 구현했고 다음은 W2 원본 보관·읽기입니다.** 최종 UI나 전체 업무 계산이 완성된 상태는 아닙니다. 현재 통합 경로표는 108품번·123경로이며 단산 이력과 기존 유보 경로를 포함합니다. 최근 공장 정정, M/H-08010 구분, 28991-4C520 전주 직사급 예외를 반영했습니다.

설계는 경로별 수불 항목 연결, 마감 계산 순서, 월별 입력·검토 화면, 결과 저장·출력의 네 가지를 다룹니다. 운영 설계 13절의 전체 초안을 14~17절에서 구체화했습니다. **월별 화면 시안과 이력 저장·수정·재확정 설계안을 작성하고, 출력 견본 대조를 9월 확정 명세 전체로 확대했습니다.** 전체 확정값 대조와 원본부터 배분 계산을 재현하는 검증은 구분합니다. 사용자 검토, 공유 촉매의 전체 총량 구분과 2JAV0 당시 자료 차이는 남아 있습니다.

추가한 `HkmgMmin020 (5).xlsx`는 매월 받을 **글로비스 실제 입고 검토 자료**입니다. 제품 입고→BOM→직사급 예외를 대조한 9월 글로비스 촉매 18,538개가 최종 마감과 품목별로 일치합니다. 희성 가공본에 있었던 2JAN0 71개는 실제 입고 원본에 없고 최종 미정산으로 확인됐습니다. 신규 원본·최종 마감·미정산 대조 결과인 **운영 설계 15절이 이전 가공본 비교보다 우선**합니다. 원본과 과거 마감은 수정하지 않았으며 자료 가져오기 기능도 아직 구현하지 않았습니다.

이력 설계는 작업 초안 자동 저장과 확정본을 구분합니다. 확정 당시 원본·BOM·경로·단가·계산 버전·월별 입력·최종 명세·미정산을 함께 남기고, 수정은 기존 확정본을 보존한 채 새 차수로 재확정합니다. 전월 재확정의 다음 달 이월 영향은 표시하되 자동 덮어쓰지 않습니다. 재출력은 저장된 확정값을 사용합니다. 백업·자료 복구·프로그램 업데이트 시 보존 조건까지 운영 설계 17절에 정리했습니다. 현재 구현한 저장은 월 작업·메모·변경 이력이며 업무 수량·확정·백업 기능은 후속 단계입니다.

## 최초 점검 기록 — 2026-10-12

아래 수치와 미확인 목록은 최초 점검 당시의 기록입니다. 이후 추가 자료·사용자 답변은 운영 설계 12~13절 및 최신 통합 경로표를 우선합니다.

- 업무 엑셀 11개를 점검했습니다. BOM과 2026년 9월~2027년 1월 촉매 소요량 파일을 받았습니다. 원본 포캐스트는 별도로 제공되지 않았습니다.
- BOM은 160행·제품/반제품 148품번·촉매 131품번입니다. 대상 H28950-/H289G0- 반제품 수불 19행은 모두 연결됩니다.
- 9월 실제 마감 151,090개·19,870,764,335원, 미정산 20,874개는 ERP 및 명세와 맞습니다. 원본부터 자동 배분하는 프로그램을 검증했다는 의미는 아닙니다.
- 현재 보고서의 `종합3(누적)`은 2026년 8월까지만 있습니다. 과거 표 간 차이와 기존/신규 계획의 버전 차이도 있어 이관 검토가 필요합니다.
- 기존 창고 연결표는 70행 중 확인완료 13행·확인필요 57행인 초안입니다. 물류 경로·집계 지점·현대기아 세부 공장·ERP 통합 마감처를 표현하도록 관리 구조를 확장해야 합니다.
- 같은 제품/촉매의 다중 납품처는 제품 수량 비율로 촉매 마감 대상 총량을 배분합니다. 글로비스는 실제 제품 입고처리 기준이며, 경유 후 기록은 중복 합산하지 않습니다.
- 세종의 울산 경로는 현대기아 울산3, 영천의 울산 경로는 품번별 울산1/5입니다. ERP는 현대 울산으로 합산합니다. 영천의 개별 품번 매핑은 아직 필요합니다.
- 완성차 직납 및 서열-전주(HSL) 상세는 사용자의 후속 설명을 기다리는 보류 항목입니다. UI 개선은 설계에 반영했으며 시안 검토 후 구현합니다.

## 관리 구조 및 다음 작업

운영 제안은 **원본 수령 엑셀·BOM·계획은 가져오고, 프로그램에서 경로·배분·단가 예외·월별 조정·확정 이력을 관리하며, 하나의 확정 데이터로 엑셀을 생성**하는 방식입니다. 동일 내용을 엑셀과 프로그램 양쪽에서 독립 수정하지 않습니다.

희성·현대기아 세부공장·ERP·미정산의 대표 출력 견본을 작성하고 같은 과거 확정 명세로 대조했습니다(운영 설계 18절). 이 과정에서 **글로비스 미입고 449개 외 전월 잔여 1개가 있어 전체 미정산은 450개**임을 확인해 이전 설명을 정정했습니다. 원본 미정산 31~35행이 근거이며 실제 마감 18,538개는 변하지 않습니다.

9월 전체 대조는 확정 명세 114행·미정산 61행·희성 84행·유미코아 69행을 포함합니다(운영 설계 19절). 품번×ERP 마감처 144건의 수량 잔액 차이는 모두 0입니다. 촉매사 원문 마감과 실제 마감이 다른 12품목 중 9품목은 기존 미입고·확정 미처리 이력으로 연결했습니다. 나머지 희성 3품목의 각 2개 입고 차이는 전표·시점을 확인하지 못해 별도로 보존했습니다. 현재 BOM에 없는 모비스 마감 21품목도 과거 확정 이력에는 포함했습니다.

9월 확정 마감의 97촉매 전체에 제품 수불·BOM 근거를 연결해 배분 검토 상태를 분류했습니다(운영 설계 20절). 사용자가 **기본은 비율 계산이며 일부 품목은 그달 예외가 있다**고 확인했습니다. 기본 계산값을 유지하면서 월별 최종 수량·사유를 수정하고 합계를 검토하는 견본을 작성했습니다. 과거 비율과 다른 8촉매를 오류나 확정된 예외로 자동 분류하지 않으며, 과거 전 건 자동 재현을 다음 단계의 필수 조건으로 삼지 않습니다.

UI와 출력 양식은 모두 검토 초안입니다. 공유 촉매 총량의 독립 산정, 누락·유보된 배분 근거 보완, 현대기아 실제 등록 형식 확인과 기존 화면의 잔액 정정 반영은 남아 있습니다. 미확인 항목은 Codex가 자료로 해결할 내용과 사용자의 월별 입력·업무 판단이 필요한 내용을 구분합니다. 필요한 판단만 구체적으로 질문하며 미확인 항목을 묵시적으로 승인된 것으로 처리하지 않습니다. 네 가지 설계가 정리되기 전에 구현 단계로 넘어가지 않습니다.

운영 설계 21절에서 **원천 수량 대조 → 해당 월 보류·해소 → 글로비스·직사급 → 일반 배분 → 월별 수정 → 확정 검산**의 총량 계산 순서를 정리했습니다. 촉매사 목록과 전주 직사급을 포함한 154촉매 중 원천 합계 일치 131·차이 22·Summary 미수록 1로 구분했습니다. 이월·당월 구성이 다른 자료를 섞어 중복 계산하거나 발주를 실제 납품으로 간주하지 않습니다. 미정산 20,874개를 사유별로 연결했으며, 과거 미정산을 차감한 검산과 새 달의 독립 산출을 구분합니다. 후속 작업은 이 계산 순서를 월 작업의 필수 입력·예외 검토·확정 조건에 연결하는 것입니다.

운영 설계 **22절에서 월 작업 규격까지 연결했습니다.** 등록된 기준과 전월 확정본을 재사용하고, 사용자 입력은 필요한 제품 분할·월별 촉매 수정·자료만으로 정해지지 않는 보류/해소 처리로 구분합니다. 사유가 확인된 미정산이나 과거 비율 차이만으로 월 확정을 막지 않으며, 새 월의 필수 자료·귀속·입력 누락과 재계산 필요 상태는 해결해야 합니다.

이후 [Graphify 설계 점검과 1차 범위](graphify-out/설계점검과_1차구현범위.md)를 작성하고, [구현 계획](docs/plans/2026-10-13-1차구현-저장구조와-개발계획.md)에서 저장 구조·계산 모듈·화면 요청·W1~W7 인수 기준까지 구체화했습니다. W1은 Python·SQLite·FastAPI와 React·TypeScript로 구현했습니다. 다음 실제 개발 단위는 **W2: 원본 보관·읽기 및 적송재고 PDF 인식·검산**입니다. 기존 Graphify 그래프는 구현 계획과 코드 추가 전 문서4개의 스냅샷이므로 현재 구조는 코드·구현 기록을 함께 확인합니다.

기존 확인 사항은 다시 질문하지 않습니다. 사용자 수정 실수를 새로운 반복 업무 규칙으로 만들지 않습니다. 답변은 한국어 존댓말로 진행합니다. 결과물은 엑셀까지이며 PPT 생성은 범위에 포함하지 않습니다.

## 다른 PC에서 이어가기

GitHub에는 소스 코드·의존성 잠금 파일·테스트·설계 문서를 보관합니다. 원본 엑셀/PDF, 검토 출력 엑셀, 실제 작업 DB와 이관 압축파일은 올리지 않습니다. 설계 문서에는 기존 업무 검토에서 확인한 품번·집계 수량이 포함돼 있으므로 원본 제외와 업무 내용 전체 비공개를 혼동하지 않습니다.

별도로 전달한 이관 ZIP을 먼저 풀고 그 안의 `먼저 읽어주세요.txt`와 `Codex_작업재개.txt`를 읽습니다. ZIP은 원자료 폴더, 검토 결과, UI 시안, SQLite 백업과 Git 이력이 있는 `Catalyst_Cutoff`를 포함합니다. 기존 `.venv`와 `node_modules`는 다른 PC로 옮기지 않으며 새 PC에서 `setup.ps1`로 다시 설치합니다. 첫 실행 시 ZIP의 `프로그램 자료` 폴더를 선택하거나 `start.ps1 -DataDir`에 그 경로를 지정합니다. 새 빈 폴더를 선택하면 이관한 월 작업이 보이지 않습니다.

이관 기준 완료 범위는 W1입니다. 다음은 W2 원본 보관·읽기와 촉매사 적송재고 PDF 인식·검산입니다. 현행 UI 시안은 `closing-focus-topnav.html`의 상단 메뉴, 좌측 묶음 목록·우측 선택 상세/수정 구성을 유지합니다. Figma 파일은 클라우드에 있으므로 같은 계정의 접근 권한을 사용합니다. Graphify의 기존 그래프는 코드 구현 전 스냅샷이며 현재 코드는 별도로 확인해야 합니다.
