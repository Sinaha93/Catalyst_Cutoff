# 2026-10-15 작업 재개: BOM·경로 편집과 선택 목록 관리

사용자의 2026-10-15 추가 요청으로 코드·테스트·이 개발 안내를 GitHub에 전달합니다. 업무자료·DB·ZIP·실제 업무 검토 기록은 제외합니다. 앞서 만든 ZIP의 미푸시 안내는 ZIP 생성 당시 상태입니다.

이 문서가 이전 작업 재개 문서보다 최신입니다. 사용자는 다른 PC에서 만든 **가상 2026-10 자료**로 프로그램을 시험 중입니다. 기능 구현과 실제 업무 검토·마감 확정은 구분합니다.

## 다음 담당자가 먼저 할 일

1. 이관 폴더의 `먼저 읽어주세요.txt`, 이 문서, `docs/operations/master-management.md` 순서로 읽습니다.
2. GitHub의 최신 `main`을 별도 폴더에 clone하거나 깨끗한 기존 체크아웃에서 pull합니다. 기준 커밋 `1ea9c9d` 이후 코드 수정·신규 파일이 이번 전달에 포함됩니다. ZIP의 `개발소스`는 전달 전 미커밋 복사본이므로 그 위에 덮어쓰기 pull/reset/clean을 하지 마세요. 최신 개발 소스는 GitHub, 작업 데이터는 ZIP의 `시험작업`을 사용합니다.
3. 실행은 이관 폴더의 `촉매 마감 실험.exe`입니다. `시험작업`이 사용자 상태이며 `시험입력자료`는 원본/생성 자료입니다. 기존 파일을 재등록하거나 월 작업을 초기화하지 마세요.
4. 월 작업에서 2026-10을 열고 기준 관리의 BOM·촉매 단가·경로 카드 상태와 현재 선택 버전을 확인합니다. 사용자 판단을 대신 승인하지 않습니다.
5. 최근 구현한 선택 목록 관리 → BOM 품목 추가/경로 수정 → 마감 검토로 돌아가 재계산 흐름을 사용자와 실제 화면에서 이어서 확인합니다. 아직 전체 가상 10월 마감을 확정하거나 결과 엑셀까지 승인한 것은 아닙니다.

## 최근 구현 내용

- 자료 등록에는 월별 원본·월계획을 두고 BOM·단가·경로 등록/수정은 기준 관리로 분리했습니다.
- 월 초기화 시 BOM·경로·단가를 보존합니다. 선택한 기준 자체의 등록 버전·파일을 비우는 기능은 별도로 존재하며 다른 월/확정본에서 사용하는 기준은 보호합니다.
- 일반 품목은 미마감 미입력 시 0으로 보고 이월+당월 입고를 마감합니다. 이미 저장한 조정과 글로비스 조건은 별도 적용합니다.
- 오류 옆 해결 가이드에서 원본 등록·기준 관리·월별 조정·근거 조회로 이동합니다. 확인 품번과 기존 값을 미리 준비하되 제품/고객사/수량을 추측하지 않습니다.
- BOM 품목 추가: 촉매 한 개에 `+ 제품 추가`, 제품마다 `+ 고객사 추가`가 가능합니다. 전체 입력을 한 번에 검증하고 새 BOM 버전 저장·이번 달 적용을 원자적으로 처리합니다.
- BOM은 제품별 촉매 구성입니다. 같은 촉매가 여러 제품에 있으면 제품별 행에 반복됩니다. 같은 제품·다른 고객사는 동일 구성의 여러 행이지만 계산에서 중복 합산하지 않습니다. 구성 충돌은 차단합니다.
- 경로·단가의 가이드 전용 수정 화면은 해당 제품/촉매를 불러오며 다른 품목을 보존한 채 새 버전 저장과 월 적용을 한 번에 처리합니다.
- 경로의 납품 경로·상세 마감공장·ERP 마감처·집계 창고·처리 상태, 월별 마감처 조정은 선택식입니다. 창고 복수 선택, 촉매별 마감처 매핑도 지원합니다.
- 선택 목록 관리: 기준 관리 상단 또는 입력란 옆에서 열고 고객사/납품 경로/상세 공장/ERP 마감처/창고를 추가·사용 중지·재사용합니다. 입력 중인 내용은 유지합니다. 기존 BOM/경로와 사용 중인 수불에서 후보를 가져오며 ERP 촉매 입고의 임의 거래처를 최종 마감처로 추정하지 않습니다.
- 목록은 자료 폴더 전체에서 공유합니다. 사용 중지는 새 선택에서 제외할 뿐 기존 기준과 과거 마감을 바꾸지 않습니다. 오타는 올바른 이름 추가 → 잘못된 이름 사용 중지 → 해당 기준에서 다시 선택/저장합니다. 직접 추가한 목록은 월/기준 초기화와 별도로 유지됩니다.
- 촉매사(희성/유미코아), 집계 자료, 수량 항목, 처리 상태는 지원하는 고정 목록입니다. 제품/촉매 품번·소요량·단가·사유는 직접 입력합니다. 새 목록 이름만 추가해서 제품 경로가 자동 연결되지는 않습니다.

## 반드시 유지할 업무 규칙

- ERP 촉매 입고 마감처는 임의 입력일 수 있습니다. 제품 납품 경로로 최종 마감처를 정하며 ERP 수량 대조와 구분합니다.
- 희성 기본 총량은 전월 촉매 마감이월+당월 촉매 입고입니다. 제품 당월 납품 수량×BOM으로 배분 근거를 만들고, 같은 촉매의 여러 제품 기여를 모아 총량을 한 번만 배분합니다.
- 제품 수불의 당월 이동은 **입고/이동처리**입니다. 출고 이동에는 전월 제품 마감이월이 섞일 수 있으므로 대신 쓰지 않습니다.
- H28950/H289G0 등 반제품의 당진 경유는 **출고/적송처리**를 사용하고 최종 기아 화성으로 연결합니다. 이동처리 오입력은 근거 확인 대상입니다.
- 글로비스는 실제 제품 입고×BOM만 마감합니다. 비율 배분·반올림 잔차로 수량을 흡수하지 않습니다.
- M/H 및 품번 접미사를 임의 합치지 않습니다. 2J540 등 특정 품번만 특별 취급하지 않습니다.
- BOM 고객사는 제품 납품 경로/최종 마감처를 대신하지 않습니다. 창고 이름만 보고 최종 공장을 추측하지 않습니다.
- 과거 평균 실적은 사용자 확인대로 마감 기준입니다. 월계획·단가는 명칭만 보고 생성/확정하지 않습니다.
- 엑셀은 기존 종합표·거래처 계산서·그래프를 유지하며 틀 고정은 사용하지 않습니다. PPT 자동 생성은 현재 범위가 아닙니다.

- TypeScript/Vite 빌드와 `git diff --check` 통과. 마지막 정적 화면 진입 파일은 `index-BG5aV8Uj.js`입니다.
- 시험은 합성/임시 자료 폴더에서 진행했습니다. 실제 가상 10월 DB를 대신 마감하거나 승인하지 않았습니다. 이번 변경 후 전체 테스트 모음을 전부 다시 실행한 것은 아닙니다.

개발 환경은 Python 가상환경과 Node/npm을 사용합니다. `setup.ps1`로 준비하고 `frontend`에서 `npm run build`합니다. 일반 실행은 `start.ps1 -DataDir <이관폴더의 시험작업>`입니다. 동시에 같은 자료 폴더를 두 프로그램에서 열지 마세요. 테스트에는 별도 임시 자료를 사용합니다.

## 이관 및 작업 원칙

- 실행용 `프로그램`과 수정용 `개발소스`는 별도 복사본입니다. 개발소스를 고친 뒤 실행 프로그램으로 반영하려면 빌드 결과와 변경 Python 파일을 함께 복사해야 합니다. 기존 실행 프로그램은 종료 후 다시 실행합니다.
- 사용자 응대는 한국어 존댓말, 확인 질문은 한 번에 하나씩 합니다. 실데이터 변경과 초기화·마감 승인을 임의로 하지 않습니다.
- 이번 전달은 사용자가 명시적으로 승인했습니다. 이후에도 사용자가 요청하기 전에는 GitHub에 임의로 푸시하지 않습니다. 업무 원본·DB·ZIP·상세 업무 검토 자료는 GitHub에 올리지 않습니다.
- 로컬 미추적 문서에도 업무 상세가 있을 수 있으므로 나중에 커밋할 때 `git add .`를 사용하지 말고 코드·테스트·안전한 문서를 구분합니다.
- 과거 인계 문서의 집계 수치/오류 목록은 당시 상태입니다. 현재 화면과 DB를 우선 확인합니다. UI는 사용자가 시험하며 다듬는 중입니다.
