## 준비

1. GitHub 저장소를 새 폴더에 clone합니다. ZIP 안의 미커밋 코드 위에 pull하지 않습니다.
2. 루트의 `setup.ps1`로 Python 환경과 프런트엔드를 설치합니다.
3. `start.ps1 -ChooseDataDir`로 실행하고 별도로 옮긴 `프로그램_개발검토_W4_3`을 선택합니다.
4. 업무 자료의 상세 상태는 별도 ZIP의 `먼저 읽어주세요.txt`와 상세 작업 재개 문서를 읽습니다. 해당 문서의 미커밋·미푸시 설명은 ZIP 생성 당시 상태입니다. 최신 코드 출처는 GitHub입니다.

## 구현 위치

- `backend/adapters`: 자료별 읽기, 검산, 원문 근거와 저장소 마이그레이션
- `backend/application/basis.py`: 제품·경로·BOM·납품 근거 연결
- `backend/application/pricing.py`: ERP 단가 후보·월별 적용 단가·계획 단가 구분
- `backend/application/reconciliation.py`: 촉매사 원천과 ERP·이월 장부 대조
- `backend/application/holds.py`: 월별 보류·해소 검증, 이력 추가, 기준 변경 감지
- `backend/application/allocation.py`: 희성 비율 배분·글로비스 실제 입고 및 총량 검산
- `frontend/src`: 기능별 검토 화면. 최종 UI는 미확정

DB 스키마는 5입니다. 스키마 1/2/3/4 이관 전 백업을 만들며 보류 처리 이력은 덮어쓰지 않습니다. 기준 변경 후 관련 근거가 바뀐 판단은 재검토합니다. 이번 개발 검증에서 실제 업무 보류 판단을 임의 확정하지 않았습니다.

## 이관 검토 후 수정

- 상세 공장별 배분·반올림을 먼저 수행하고 ERP 지역 합계를 그 결과에서 계산합니다. 글로비스 실제 입고는 별도 고정값입니다.
- 미확인 경로도 BOM에서 촉매 연결을 유지하여 해당 촉매를 다른 경로에 전량 배분하지 못하게 합니다.
- 엑셀 총량의 이월·입고를 원천 구성과 대조합니다. 원천 차이 또는 관련 근거 변경이 있으면 계산 결과를 적용하지 않습니다.
- `dependencies.py`에서 관련 행의 내용과 읽기 규칙을 비교합니다. 다른 품목 변경·행 이동·동일 원본 재읽기는 저장된 보류 판단을 무효화하지 않습니다. 전체 원본 ID·해시는 기존 이력에 계속 보존합니다.
- 새 양식의 촉매총량 연결근거ID는 품목별입니다. 구 양식은 재확인해야 하며, 구 방식으로 저장한 보류 이력도 보존하되 자동 재승인하지 않습니다. 공장수량 분할 양식은 전체 연결 기준 변경 시 재확인하는 기존 규칙을 유지합니다.
- 회귀 사례는 `tests/test_review_regressions.py`에 추가했습니다. 실제 원본·업무 DB는 변경하지 않았습니다. 이 수정은 아직 커밋·푸시하지 않았습니다.

1. 원천 선택·업무 이월 수정·해제를 별도 이력으로 저장하고 관련 기준 변경을 감지합니다.
2. 유미코아 PDF와 Summary를 연결하며 원문 마감과 차이를 검토합니다. 월별 수량·가격·제품 공장 구분을 화면에서 수정합니다.

4. 불변 확정본, 재확정 버전, 이전 버전 재출력, 특정 전월 확정본 연결, 보류 단가별 해소, XLSX 검산, 원본 포함 ZIP 백업을 연결했습니다.
