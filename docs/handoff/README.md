# W4.3 개발 재개 안내

2026-10-13 사용자의 명시적 요청에 따라 W2.2~W4.3 코드·테스트와 실행 안내를 GitHub에 전달합니다. ZIP과 업무 원본, DB, 상세 업무 검토 기록은 별도 이관 자료에서 확인합니다. 후속 작업의 push도 별도 요청이 있을 때만 진행합니다.

## 준비

1. GitHub 저장소를 새 폴더에 clone합니다. ZIP 안의 미커밋 코드 위에 pull하지 않습니다.
2. 루트의 `setup.ps1`로 Python 환경과 프런트엔드를 설치합니다.
3. `start.ps1 -ChooseDataDir`로 실행하고 별도로 옮긴 `프로그램_개발검토_W4_3`을 선택합니다.
4. 업무 자료의 상세 상태는 별도 ZIP의 `먼저 읽어주세요.txt`와 상세 작업 재개 문서를 읽습니다. 해당 문서의 미커밋·미푸시 설명은 ZIP 생성 당시 상태입니다. 최신 코드 출처는 GitHub입니다.

## 구현 위치

- `backend/adapters`: 자료별 읽기, 검산, 원문 근거와 저장소 마이그레이션
- `backend/application/basis.py`: 제품·경로·BOM·납품 근거 연결
- `backend/application/pricing.py`: ERP 단가 후보·월별 적용 단가·계획 단가 구분
- `backend/application/reconciliation.py`: 촉매사 원천과 ERP·이월 장부 대조
- `backend/application/holds.py`: 월별 보류·해소 검증, 이력 추가, 기준 변경 감지
- `backend/application/allocation.py`: 희성 비율 배분·글로비스 실제 입고 및 총량 검산
- `frontend/src`: 기능별 검토 화면. 최종 UI는 미확정

DB 스키마는 3입니다. 스키마 1/2 이관 전 백업을 만들며 보류 처리 이력은 덮어쓰지 않습니다. 기준 변경 후 기존 판단을 그대로 재사용하지 않습니다. 이번 개발 검증에서 실제 업무 보류 판단을 임의 확정하지 않았습니다.

## 다음 단계

1. 원천 차이를 추적하고 근거 보완·선택 이력을 저장합니다.
2. 유미코아 최종 마감과 월별 보류를 연결합니다.
3. 월별 보류 목록 완료 및 보류 없는 품목의 일괄 처리를 구현합니다.
4. 마감 수량에 적용 단가를 연결하고 금액·전체 수지를 검산합니다.
5. 월 확정 버전, 다음 달 이월, 최종 엑셀 출력과 UI 통합을 구현합니다.

모든 품번에 공통 배분 규칙을 적용합니다. 단일 품번을 특별 취급하지 않습니다. 같은 촉매가 여러 제품에 쓰이면 기여 수량을 합산해 총량을 한 번만 배분합니다. 기존 보고서의 미마감 수량은 비교 근거이며 새 월의 보류 판단으로 자동 채택하지 않습니다. 최종 UI 통합 시 별도 이관 자료의 `closing-focus-topnav.html`을 참고합니다.

사용자 응대는 한국어 존댓말로 하며 필요한 확인은 하나씩 진행합니다. 이번 전달은 작업을 이어갈 준비이며 후속 기능 구현을 자동으로 시작하지 않습니다.
