# 검토 폴더 전체 검토 결과

검토일: 2026-10-08

## 1. 결론

검토 폴더의 7개 엑셀을 확인했다. 현재 2026년 9월 결과물의 사업장별 마감 수량·금액, 종합, 누적 실적과 단가 계산은 일치한다. 기존 결과를 확인하고 초기 데이터를 이관할 자료는 갖추어져 있다.

희성 원본부터 같은 결과를 자동으로 다시 만드는 기능에는 BOM, 월계획, 희성 적송재고 원본, 글로비스 실제 입고 확인 출처 및 전체 창고-마감처 규칙 연결이 필요하다. 파일 안에 이미 있는 데이터와 앞으로 매월 받아야 할 원본은 구분한다.

이번 검토에서는 업무 엑셀을 수정하지 않았다. 모든 월의 과거 원본 대조나 실제 Excel에서 외부 참조를 새로 계산한 검증은 아니다.

## 3. 현재 결과물 검증

| 검증 항목 | 결과 |
|---|---:|
| 9월 실제 마감 수량 | 151,090개 |
| 9월 실제 마감 금액 | 19,870,764,335원 |
| 전월 미정산 | 12,021개 |
| ERP 촉매 입고 | 159,943개 |
| 당월 말 미정산 | 20,874개 |
| 당월 말 미정산 금액 | 2,662,318,812원 |

`12,021 + 159,943 - 151,090 = 20,874`로 일치한다. ERP 전체 160,776개에서 제외하기로 한 컨버터 833개를 제외했다. 보고서에 별도 제외 설명은 필요 없다.

품번·마감처별로도 `실제 마감 + 당월 말 미정산 - 전월 미정산`과 ERP 입고를 대조했다. 지정한 컨버터 제외를 적용하면 수량 차이가 없다. 이는 현재 결과물의 수량 검증이며 BOM 없이 제품 배분 알고리즘을 재현했다는 의미는 아니다.

마감 명세 114개 항목의 단가는 등록 단가와 일치하고, 명세 금액도 수량 × 단가와 일치한다. 사업장별 명세 합계, 각 사업장 9월 실적, 전체 마감 및 누적 9월 실적이 일치한다.

| 수정했던 누적 월 | 마감 수량 | 마감 금액 |
|---|---:|---:|
| 2026년 4월 | 160,541개 | 18,671,202,698원 |
| 2026년 8월 | 105,925개 | 14,712,756,099원 |

현재 누적의 실적 행에 빈 수량·금액은 없고, 기존 수식의 저장된 결과에도 오류 값은 없다. 과거 전체 값의 원본 검증 및 과거 표 사이의 전수 대조까지 완료했다는 뜻은 아니다.

## 5. 자동화에 반영할 발견 사항

### 5.1 희성 가공 후보와 최종 마감의 차이

- 세종공업의 289F1-4A640, 289K1-4A650, 289K1-4A660은 가공 자료에 각각 595개, 최종 마감에 각각 593개다.
- 글로비스의 28957-2JBE0은 가공 자료에 71개, 최종 마감에 0개다.
- 현재 최종 마감·미정산과 ERP 수량은 맞는다. 가공 수량으로 무조건 되돌리지 않는다. 프로그램은 가공 후보, ERP 대조, 실제 정산 판단 및 수정 근거를 구분한다. 이 차이를 모든 미래 월에 고정 적용하지 않는다.

### 5.2 기존 미정산 실수의 이관 정리

후속 수정 완료: 사용자가 중복 입력 실수임을 재확인하고 삭제를 요청했다. 기존 파일의 39·40행에 전월 이월과 당월 입고를 보존하면서 실제 마감을 0으로 고치고, 중복 추가된 51·52행의 명세 내용을 지웠다. 서식과 다른 행의 참조를 보존하기 위해 행 번호는 이동하지 않았다. 두 품번은 각각 한 번만 남고 미정산 263개·287개를 유지한다. 전체 미정산 20,874개·2,662,318,812원과 최종 마감 합계는 변하지 않았다. 아래 표는 수정 전 발견 기록이다. 이를 추가 업무 규칙이나 미해결 이관 과제로 취급하지 않는다.

사용자가 미마감이라고 확인한 위아 28533-08070과 28533-08110은 현재 미정산 시트에 각각 두 행이 남아 있다.

| 품번 | 앞 행의 표현 | 뒤 행의 표현 | 실제 이관할 상태 |
|---|---|---|---|
| 28533-08070 | 이월 95 + 매입 168, 마감 263, 미마감 0 | 매입 263, 마감 0, 미마감 263 | 전월 95 + 당월 입고 168, 실제 마감 0, 미정산 263 |
| 28533-08110 | 이월 96 + 매입 191, 마감 287, 미마감 0 | 매입 287, 마감 0, 미마감 287 | 전월 96 + 당월 입고 191, 실제 마감 0, 미정산 287 |

전체 마감·잔여 합계는 맞지만 두 행을 실제 거래로 모두 이관하면 매입·마감이 중복된다. 사용자 확인과 ERP에 맞춘 단일 명세로 이관한다. 이번 검토에서 기존 엑셀을 수정하지는 않았다.

### 5.3 유미코아의 표기를 확정값으로 그대로 쓰지 않음

- 위아 미마감 7개 품목은 최종 미정산 1,764개로 반영되어 있다. 원자료의 마감 표기가 실제 마감을 보장하지 않는다.
- 납품 Summary의 28533-07010은 전월적송 0, Total 납품 24, 마감 표기 46, 당월적송 -22다. ERP 입고는 38, 기존 미정산 전월 이월은 8이다. 실제 미마감 46은 ERP·이월에 맞지만 촉매사 표기만으로는 같은 결과가 나오지 않는다.
- ERP, 촉매사 표기, 실제 마감·미마감 및 사용자 판단을 따로 저장한다. 원본 셀을 임의로 변경하지 않는다.
- 주차 시트에는 전월 말·다음 월 날짜와 겹치는 날짜가 있다. Summary와 주차를 동시에 더하지 않으며 세부 검증은 실제 날짜 기준으로 한다.
- 고객사 이름이 현대위아여도 모비스로 마감하는 품목이 있으므로 고객사 문자열만으로 배정하지 않는다.

### 5.4 제품·반제품 수불의 집계 기준

- 제품의 세종공업(화성) → 현대 울산 사례는 당월 입고 이동처리 8,400개를 사용하고 전월 제품 이월 480개를 비율에서 제외한다.
- OEM·연구소·포레시아·세정 등을 포함한 21종 창고를 모두 현재 10개 마감처로 자동 배정할 수 없다. 대상 경로만 관리표로 연결한다.
- 반제품의 H28950-/H289G0-는 19개 행, 출고 적송 합계 16,037개다. 이를 촉매 마감에 그대로 합산하지 않고 BOM으로 연결해 기아 화성 배분 근거로 사용한다.
- 반제품의 출고 이동처리 예외는 사용자 확인 규칙이다. 현재 예시에는 그 열이 없으므로 예외 전체 발생 여부는 검증할 수 없다. 다음 달 열이 생기면 제목 의미로 읽는다.
- 당진 반제품과 이후 완제품이 같은 촉매 흐름이면 양쪽을 중복 합산하지 않는다.

### 5.5 단가와 외부 참조

- 실제 마감 114개 단가는 모두 일치했다. 미정산 28957-2JDF0의 131,518원은 사용자 확인된 가단가이므로 전산 1원으로 바꾸지 않는다.
- 등록 단가에는 28950-3N500, 289G0-2M110의 서로 다른 중복 단가가 있다. 현재 마감 명세에는 적용 차이가 없지만 향후 사용 시 첫 값을 임의 선택하지 않는다.
- 기존 파일의 외부 촉매 관리 현황·과거 단가·마감 참조는 저장된 값으로 읽을 수 있다. 다른 컴퓨터에서 외부 파일 없이 재계산할 수 있다고 보장하지 않는다. 새 결과물은 프로그램 관리표와 확정 데이터로 생성한다.
- 월이 지난 ERP의 거래명세표 발행 상태는 실제 마감 시점과 다를 수 있다. 조회 기간, 추출 기준일, 실제 마감 판단 기준일을 기록한다.
- 희성 글로비스 시트의 11개 입고 행에는 번호가 없는 추가 행도 있다. 번호가 비거나 품번·수량이 같다는 이유만으로 삭제하지 않는다.

## 6. 지금 진행할 수 있는 범위

현재 자료로 결과물 구성·파일 읽기 규칙·초기 데이터 이관·ERP 및 미정산 검증·기존 확정값 기반 엑셀 출력의 구현 계획을 작성할 수 있다. 단가 파일과 과거 입고 파일을 더 요청할 필요는 없다.

희성 원본부터 자동 생성하려면 BOM을 받은 뒤 관련 제품·반제품 수량을 계산하고, 적송재고 원본, 전체 창고 경로, 글로비스 입고의 출처·기준일·배분 적용 순서를 연결해야 한다. 월계획은 원본 수령 후 추가한다.

## 7. 다른 컴퓨터에서 이어가기

설계와 검토 문서는 GitHub에 보관한다. 실제 업무 엑셀과 API 키는 이번 문서 업로드에 포함하지 않는다. 파일 분석을 이어가려면 검토 폴더의 7개 엑셀과 상위 폴더의 희성 원본 9월 우신공업 출하실적.xlsx를 준비한다. BOM은 사용자가 추후 제공한다.

파일 위치: 현재 PC의 `D:\Documents\CODEX\촉매마감_rev1\검토`. 희성 원본은 상위 폴더에 있다. 다른 컴퓨터에서는 경로가 달라도 자료 역할로 등록한다.

외부 촉매 관리 현황·과거 단가 파일을 옮기지 않으면 기존 수식 재계산은 제한될 수 있다. 프로그램 관리표로 대체하면 이 의존을 제거할 수 있다. 과거 입고용 월품목구매현황은 매월 필수 파일이 아니다.

검토 범위는 전체 시트의 저장된 수식 결과·오류·외부 참조, 마감 명세 계산·단가·누적·ERP 수량이다. BOM 미제공으로 촉매별 제품 배분을 원본에서 재계산하지 않았고, 실제 마감 시점 글로비스 입고와 과거 전체 월 원본은 별도 검증 대상이다.
