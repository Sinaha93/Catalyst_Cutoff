검토일: 2026-10-12. 대상: 현재 작업 폴더의 업무 엑셀 11개, 저장소 문서, 사용자 확정 사항.

이 문서는 업무 규칙과 관리 역할의 기준 문서다. 이전 기록과 다르면 최신 사용자 확인과 실제 파일 점검을 우선한다. **확인된 업무 규칙**, **자료에서 검증한 사실**, **구현 제안**, **추후 확인 사항**을 구분한다. 아래 절별 구현 전 표현은 해당 검토 당시의 기록이다. 현재 실행 상태는 README와 W1 구현 기록을 함께 확인한다.

**2026-10-13 진행 단계 정정:** 현재는 구현 전 상세 설계 단계다. 경로표의 마감처 정리를 전체 설계 완료로 보지 않는다. 아래 13절에서 경로별 수불 연결, 계산 순서, 월별 입력·검토 화면, 결과 저장·출력을 구체화한다. 사용자 요청은 이 네 항목의 설계를 이어가는 것이며 구현 착수를 의미하지 않는다. 이전 절의 최초 점검 숫자와 미확인 목록은 당시 기록이고, 경로별 후속 정정은 12절을 우선한다.

**최신 구현 상태 — 2026-10-13:** 22절 이후 Graphify 점검과 1차 범위 정리를 거쳐 [저장 구조와 개발 계획](../plans/2026-10-13-1차구현-저장구조와-개발계획.md)을 작성하고 W1 월 작업·메모 저장·재실행 복원을 구현했다. 다음 실제 개발 단위는 W2 원본 보관·읽기다. 실제 업무 수량 계산·확정·출력과 최종 UI 채택은 아직 완료하지 않았다. 아래 절별 ‘다음 작업’은 작성 당시의 순서 기록이다. [업무 프로세스](../process/촉매마감-업무프로세스.md)와 [현재 리뷰](2026-10-13-코드와-업무설계-리뷰.md)를 함께 참조한다.

## 1. 전체 판단

- 기본 자료는 상당 부분 확보했다. BOM·소요량 파일을 다시 요청할 단계가 아니다. 대상 반제품 19행의 BOM 연결도 충족한다.
- 9월 현재 마감 수량·금액과 ERP·미정산은 대조가 맞는다. 이는 기존 결과 검증이며, 원본부터 같은 결과를 자동 계산하는 기능을 완성했다는 뜻은 아니다.
- 가장 먼저 고칠 설계는 **품번별 물류 경로, 현대·기아 입력용 세부 공장, ERP 통합 마감처의 분리**다. 창고명과 최종 마감처만 연결하는 표로는 중복과 다중 납품처를 처리할 수 없다.
- 엑셀마다 판단·수량·단가·누적을 따로 수정하는 구조를 끝내고, 프로그램의 하나의 확정 데이터로 희성 가공표·ERP 통합표·현대기아 세부표·보고서·누적을 생성하는 구성을 제안한다.
- 기존 누적·계획·평균에는 이관 전 정리가 필요하다. 과거 자료 전체가 검증 완료되었다고 처리하지 않는다.

| 이벤트·A/S | 계획에 없다는 이유로 실제 사용·수불을 제외하지 않음 | 계획 대비와 실제 거래 검증의 범위 분리 |
| PUPE·E2.9·서열-전주(HSL) | 물류 유형 설명은 받았고 상세는 사용자가 추후 정리 | 보류 유지. 자동 배정·0 처리·분석 대상에서 삭제하지 않음 |
| 정/가단가 | ERP 등록 단가와 승인 적용 단가 분리. 28957-2JDF0의 승인 가단가 131,518원 보존 | 적용 기간·월별 근거·변경 이력 관리 |
| 실제 미마감 | 유미코아 원본의 ‘마감’ 표기와 실제 마감은 다를 수 있음. 확인된 위아 7품목 미정산 1,764개 유지 | 원본 표기·실제 판단·ERP 대조를 분리 저장 |

기존 28533-08070·08110의 중복은 수정된 수기 실수다. 현재 각각 한 번, 미정산 263개·287개로 존재한다. 이를 미해결 질문이나 매월 반복하는 예외 규칙으로 다시 만들지 않는다.

## 5. 무엇을 엑셀로, 무엇을 프로그램에서 관리할 것인가

다음은 운영 구조 제안이다. 프로그램 구현·이관 완료를 뜻하지 않는다. **같은 항목을 엑셀과 프로그램에서 각각 수정하는 두 개의 기준본을 만들지 않는다.**

| 정보 | 기준 관리 위치 | 운영 방법 |
|---|---|---|
| ERP 입고·제품/반제품 수불 | ERP에서 받은 원본 엑셀 | 매월 가져오기. 프로그램은 원본 보관·해석·대조만 수행 |
| 희성·유미코아 원본 | 촉매사 수령 엑셀 | 파일·월·버전별 보관. 원본 셀 수정 대신 별도 조정 기록 |
| 제품→촉매 구성·소요량 | 당분간 기존 BOM 엑셀 | 수정본 가져오기→차이 검토→적용일 지정. 마감은 승인한 BOM 버전 사용. 프로그램에서 같은 구성의 독립 수정본을 운영하지 않음 |
| 물류 경로·집계 지점 | 프로그램 기준 관리 | 품번별 여러 경로, 유형, 창고, 집계 포함/추적, 수량 열, 적용 기간. 엑셀은 일괄 등록·내보내기 수단 |
| 현대기아 세부 공장→ERP 통합처 | 프로그램 기준 관리 | 울산1/3/5→ERP 울산 등 연결. 직접 납품처·실물 도착지와 별도 항목 |
| ERP 등록 단가 | ERP 단가 엑셀 | 버전별 가져오기. BOM 단가 시트는 참고 사본으로 취급 |
| 가단가·단가 예외 | 프로그램 기준/월별 조정 | ERP 단가와 함께 저장하고 기간·사유·승인 기록. 과거 확정 금액 재계산 금지 |
| 소요량·월계획 | 외부 작성 엑셀 | 월·계획 버전별 가져오기. 기준 계획과 수정 전망을 구분해 보관 |
| 제품 마감 수량 직접 입력 | 프로그램 월 마감 화면 | 필요한 품번만 마감처별 입력. 지난달 경로 목록은 재사용하되 수량은 자동 이월하지 않음 |
| 글로비스 실제 입고 | 받은 실제 입고 원본 + 프로그램 월별 확인 | 자료가 있으면 가져오기, 수동 확인이면 수량·날짜·근거 기록 |
| 마감 배분·미정산·수정 사유 | 프로그램 월별 데이터 | 계산 후보와 확정값 분리. 사용자 검토·조정 후 확정 |
| 과거 마감·평균·누적 | 프로그램 확정 이력 | 최초 엑셀 이관 시 검증 상태 표시. 이후 월 확정에서 자동 누적 |
| 희성 가공표·ERP용·현대기아용·종합 보고서 | 프로그램 생성 엑셀 | 동일 확정 버전에서 생성. 출력 엑셀을 고친 경우 프로그램에 변경을 반영해 새 버전으로 확정 |

BOM의 기존 고객사/마감처 열은 당장 삭제하지 않는다. 물류 경로 후보의 출처로 남기되 자동 마감 판단은 프로그램의 승인된 경로를 사용한다. BOM 구성 변경과 경로 변경을 독립적으로 적용하고 충돌을 표시한다.

## 6. 통합할 것과 분리할 것

**통합:** 하나의 월 마감 작업 안에서 희성 가공 작성→유미코아 확인→ERP 대조→실제 마감 확정→출력까지 이어간다. 화면을 여러 프로그램으로 나누거나 희성 가공 파일을 다시 수동 입력하게 만들지 않는다. 다만 희성 가공 엑셀은 기존 업무용 중간 출력으로 계속 만들 수 있다.

**분리:** 원본, 해석 결과, BOM 구성, 경로 규칙, ERP 단가, 승인 예외, 월별 입력, 계산 후보, 확정 명세를 구분한다. 물류에 쓰는 제품 수량과 매입 마감할 촉매 총수량, 제품 이월과 촉매 미정산도 각각 보존한다.

**공통으로 계산:** 품번 정규화, 출처 추적, 승인 경로 집계, BOM 적용, 다중 마감처 비율, 금액, 미정산, 월 확정과 출력.

**촉매사별로 읽기·총량 구성:** 희성은 전월 촉매 이월+당월 출하를 기준으로 배분 후보를 만든다. 유미코아는 Summary/주차 원본과 실제 미마감 판단을 우선 연결한다. 사용자 확정 공통 비율 규칙은 다중 배분이 필요한 경우 적용하되, 이미 구분된 유미코아 명세 전체를 다시 희성 방식으로 재배분하지 않는다. Summary와 주차 합계를 동시에 더하지 않는다.

기존 설계의 ‘유미코아는 희성처럼 일괄 배분하지 않음’과 최신 ‘다중 마감처는 공통 비율 사용’은 읽기/총량 준비 단계와 필요한 배분 단계를 나눠 반영한다. 각 유미코아 품목의 배분 필요 여부는 원본과 승인 경로로 판정한다.

## 7. 필요한 프로그램 데이터 구조

| 데이터 | 최소 관리 항목 |
|---|---|
| 원본 등록 | 파일 ID·해시·업무 월·조회 기간·추출일·자료 종류·버전·시트/행 위치 |
| BOM 버전 | 제품/반제품·촉매·소요량·사용 구분·적용 기간·원본 |

| 집계 지점 | 경로 ID·제품/반제품 자료·ERP 창고·수량 의미/열·집계 대상/후속 추적·중복 관계 |

| 배분 근거 연결 | 확정 명세와 원래 제품·경로·BOM 버전·사용한 수량·반올림/조정 내역의 연결 |

같은 촉매가 여러 제품에 들어가면 제품별 근거를 먼저 합산한 뒤 촉매 총량을 한 번 배분한다. 경로마다 촉매 총량 전체를 복제하지 않는다. 확정 명세는 동일 가격·같은 귀속 범위로 합칠 수 있으나 제품/경로별 근거 연결은 남긴다. 월중 단가가 다르면 별도 명세를 유지한다.

원본 파일 보관소와 로컬 데이터베이스(SQLite 등 후보)를 사용하는 구성을 제안한다. 사용자에게는 DB 파일이나 표 구조를 직접 편집하게 하지 않고 화면에서 관리하게 한다. 원본·DB·설정을 함께 복구할 수 있어야 한다. 실제 업무 엑셀과 키는 코드 저장소에 넣지 않는다.

## 8. 계산 흐름과 출력

1. 대상 월과 자료 역할을 지정해 원본을 등록한다. 동일 해시 재등록은 중복 집계하지 않는다.
2. 품번·거래처 별칭을 정규화하되 원문을 보존한다. R600 제거는 촉매에만 적용한다. 제품 M/H, `_US`, `_CKD` 구분을 임의 삭제하지 않는다.
3. 사용 BOM 버전과 경로를 연결하고 집계 지점을 선택한다. 후속 이동 기록은 보존하되 배분 근거에서 다시 더하지 않는다.
4. 경로 자료만으로 분할 불가능한 품번의 제품 수량을 월별로 입력한다. 미입력, 0, 미확인을 구분한다.
5. 촉매별로 제품 근거×BOM 소요량을 마감처/세부 공장별로 집계하고 비율을 구한다. 이 값은 일반 마감처의 촉매 마감 수량이나 상한이 아니다.
6. 촉매사별 대상 총량과 예외를 연결해 배분 후보를 만든다. 글로비스 실제 입고 및 미입고 잔여는 별도 보존한다.
7. 반올림·단가·ERP·이월·실제 미마감·월별 조정을 대조하고 검토한다.
8. 하나의 확정 버전을 저장하고 그 버전에서 ERP 통합표, 현대기아 세부표, 희성 가공표, 미정산, 종합·누적 보고서를 생성한다.

일반 배분은 소수점 반올림 후 합계 잔여를 정해진 순서로 조정하고 이력을 남긴다. 글로비스의 실제 미입고 잔여를 반올림 오차로 취급해 다른 마감처로 넘기지 않는다. 소요량 파일의 **올림**은 계획 작성 방식이고 마감 배분의 **반올림**과 별개다.

글로비스와 일반 마감처가 공유하는 촉매의 전체 배분 순서는 아직 연결 작업이 남았다. ‘전체 촉매에서 글로비스 실제 입고분만 빼고 나머지 전부를 일반 마감’하는 공식을 확정하지 않는다. 글로비스 대상분·실제 입고 정산분·미입고 이월·일반 배분분의 관계를 실제 월별 사례로 확인해야 한다.

현대 울산 ERP 수량은 울산1·3·5 및 승인된 다른 세부 귀속의 합과 일치해야 한다. 세부 공장을 모르면 ERP 통합처가 알려졌더라도 현대기아용 출력은 미완성으로 표시한다. 과거 확정 이관의 ERP 결과를 임의 세부 공장으로 분해하지 않는다.

## 9. 만들 화면과 사용 흐름

| 화면 | 사용자 작업 |
|---|---|
| 월 마감 현황 | 자료 등록 상태, 검토 필요 건수, 현재 마감/미정산, 확정 버전 확인 |
| 자료 가져오기 | 파일 선택, 대상 월·종류 확인, 수정본 차이와 누락 확인 |
| 마감 검토 | 품번 검색, ERP/촉매사/계산후보 비교, 출처, 조정 사유 확인 |
| 제품별 분할 입력 | 제품 한 건의 여러 마감처 수량과 비율 입력, 연결 촉매 배분 후보 표시 |
| 기준 관리 | BOM 버전·품번별 경로·집계 지점·세부 공장/ERP 매핑·단가 예외 관리 |
| 확정·출력·이력 | 마감 확정, 세부/통합 보기, 엑셀 생성, 이전 버전 비교·재확정 |

매달 기준표 전체를 다시 작성하지 않는다. 최초 등록 후 다음 달에는 신규 품번·변경 경로·자료 차이·당월 직접 입력·실제 미마감만 검토하는 것이 목표다. 확인은 한 번에 한 건씩 진행할 수 있게 한다.

UI는 개발 마지막 장식 단계로 미루지 않는다. 구현 전에 대표 화면과 입력 흐름을 먼저 검토한다. 웹/업무 프로그램 사례 또는 사용자가 제공하는 시안 이미지를 참고할 수 있다. 지금은 설계 반영이며 별도 촉매 발주 앱의 수정이나 UI 이미지 제작을 진행한 것이 아니다.

## 13. 구현 전에 구체화할 네 가지 설계 — 2026-10-13 초안

### 13.1 경로 관리 구조

통합 엑셀에 108품번·123경로를 정리했다. 이는 양산 108품번이라는 뜻이 아니며 단산 이력과 기존 유보 경로를 포함한다. 앞서 남긴 7건의 처리와 마감처 정리는 완료했으나, 모든 경로의 수불 항목 연결과 계산 검증까지 완료했다는 뜻은 아니다. 현재 근거표의 104경로는 처리 방법이 `월별 제품 실적 비율 배분`으로만 표시되어 있다. 다른 문서에 있는 집계 기준까지 연결해 경로별로 사용할 수량을 명확히 해야 한다.

| 관리 단위 | 저장할 내용 | 월마감 때의 사용 |
|---|---|---|
| 제품별 경로 | 전체 품번, 납품처·경유지·최종 도착지, WCC/UCC 등 유형, 운영 상태 | 동일 품번의 여러 경로를 각각 선택. M/H·접미사 유지 |
| 수불 연결 | 자료 종류, 창고, 수량 항목 이름, 해당 양식의 열, 집계/후속 추적 구분, 원본 근거 | 한 이동을 한 번만 집계. 열 문자만 고정하지 않고 양식과 항목을 함께 관리 |
| 마감처 연결 | 촉매사 자료에 표시할 공장, 현대기아 세부 공장, ERP 통합 마감처 | 출력마다 필요한 이름을 사용. 이름이 같다는 이유로 납품처와 마감처를 합치지 않음 |
| 촉매별 예외 | 촉매 품번, 적용 범위, 마감처·수량 처리 예외, 근거 | 28991-4C520 직사급처럼 제품 경로보다 먼저 적용 |
| 변경 이력 | 이전 값, 새 값, 변경 이유, 적용할 월, 확인 근거 | 기준 변경이 이미 확정한 월을 바꾸지 않음 |

사용자가 매 행마다 시작월·종료월을 채우는 방식은 피한다. 최초 가져오기 때 적용할 마감월을 한 번 선택하고, 변경 시 `이번 작업 월부터 적용` 또는 특정 월을 지정하는 흐름을 제안한다. 종료월은 새 버전과 연결해 관리한다. 근거 없는 과거 적용월은 만들지 않는다.

수불 연결의 완료 예시는 세종 M28950-2JAV0이다. 제품 수불의 세종공업(화성) 당월 입고 이동처리 J100 8,400개를 울산3 비율 근거로 사용하고, 출고 이동처리 N100 8,880개와 후속 현대 울산 창고 기록을 다시 더하지 않는다. 당진 반제품은 승인된 출고 적송 기준을 사용한다. 이 사례를 근거로 모든 창고에 J열을 일괄 적용하지 않는다.

경로 상태는 `마감처 연결`, `수불 기준 연결`, `계산 사례 대조`로 구분해 보여주는 것을 제안한다. 한 칸의 ‘설정 완료’만으로 세 단계를 모두 완료한 것처럼 표시하지 않는다. 단산품은 실제 거래가 생긴 월의 이력 계산에 포함할 수 있으나 양산 목록으로 자동 복귀하지 않는다.

**남은 설계 작업:** 기존 자료·검토 기록에서 경로별 수불 항목과 후속 이동 관계를 채우고, 자료만으로 결정되지 않는 사례만 구분한다. 완성차·HSL 상세는 기존 유보를 유지한다.

### 13.2 마감 계산 순서

| 순서 | 처리 | 다음 단계에 넘길 값 |
|---|---|---|
| 1 | 대상 월, 원본 수정본, 전월 확정 이월, 적용 BOM·경로·단가를 선택 | 이번 계산에 쓸 자료 목록과 버전 |
| 2 | 당월 거래에서 대상 품목을 추출. 개발·A/S·단산 실적도 보존. 제외 촉매는 별도 규칙 적용 | 이번 달 처리 대상과 누락/충돌 목록 |
| 3 | 경로별 집계 지점의 수불 수량을 읽고 후속 이동 중복을 제외. 필요한 품목에만 월별 제품 수량 입력 적용 | 제품·경로별 배분 근거 수량과 출처 |
| 4 | 제품 수량×BOM 소요량을 촉매·세부 공장별로 합산 | 촉매별 배분 비율의 분자와 분모 |
| 5 | 촉매사별 마감 대상 총량을 구성. 희성은 전월 마감이월+당월 출하, 유미코아는 원본 마감과 실제 미마감 판단을 구분 | 배분할 총량, 이미 귀속된 수량, 미마감·조정 항목 |
| 6 | 직사급·글로비스·일반 배분을 구분하여 수량 후보 산출 | 처리 근거가 다른 수량을 분리한 마감 후보 |
| 7 | 일반 배분의 정수 반올림과 합계 차이 조정. 확인된 월별 수정은 별도 기록 | 계산 수량, 반올림 조정, 사용자 조정, 최종 후보 |
| 8 | 적용 단가로 금액 계산, ERP 입고·이월·실제 마감·미정산 대조 | 차이와 사유가 보이는 검토 명세 |
| 9 | 검토 후 월 확정 버전 저장 | 모든 출력이 함께 참조하는 확정 데이터 |

일반 배분식은 `배분할 촉매 총량 × (해당 세부 공장의 제품 수량×소요량 합계 / 해당 배분 범위 전체 근거 합계)`다. 제품 수량을 촉매 총량이나 상한으로 쓰지 않는다. 같은 촉매를 쓰는 여러 제품의 근거는 먼저 합치며 촉매 총량을 제품마다 복제하지 않는다. 직접 입력은 해당 범위의 자동 수량을 대체하며 둘을 더하지 않는다.

개발·A/S는 실제 거래와 별도 경로를 연결한다. 해당 수량이 원본 총량에 포함되어 있는지 먼저 확인한 뒤 따로 귀속하여 중복을 막는다. 확인된 이월 조정·실제 미마감은 사유와 함께 보관한다. 수량 차이를 없애기 위한 임의 보정은 만들지 않는다.

**6번에서 아직 결정하지 않은 부분:** 글로비스와 일반 납품처가 공유하는 촉매의 글로비스 대상분, 실제 입고 마감분, 미입고 이월분, 일반 배분분을 어떤 근거로 구분하는가. 실제 입고 기준 자체는 이미 확정됐다. `총량−글로비스 실제 입고=전부 일반 마감`으로 임의 확정하지 않는다. 28991-4C520은 전주 직사급 예외가 먼저이며 글로비스 제품 입고량을 자동 복사하지 않는다. 실제 월별 사례로 이 부분을 대조한 뒤 순서를 확정한다.

반올림은 기존 합의대로 양수 0.5 올림을 적용한다. 차이는 조정 가능한 배분 수량이 큰 순서, 동률은 관리표 순서로 정리한다. 글로비스 확정 수량과 업무상 미마감 잔여를 반올림 조정에 포함하지 않는다. 제품 근거 합계 0, 누락, 음수·반품은 서로 구분하며 자동 균등 배분하지 않는다.

### 13.3 월별 입력·검토 화면

화면 흐름은 `자료 확인 → 필요한 수량 입력 → 마감 검토 → 확정·출력`으로 제안한다. 매월 전체 경로표를 다시 확인하게 하지 않는다.

| 화면 영역 | 보여줄 것 | 사용자가 입력할 것 |
|---|---|---|
| 상단 작업 정보 | 대상 월, 자료 수정본, 마지막 계산 시각, 확정 여부 | 대상 월·자료 선택 |
| 이번 달 필요한 입력 | 자료만으로 분할 불가한 품번, 누락 근거, 실제 미마감 사유 | 필요한 건만 입력. 이미 확인한 경로는 재질문하지 않음 |
| 품번별 공장 분할 | 제품 품번·납품처, 연결된 공장, 자동 근거, 입력 합계, 비율 | 공장별 당월 제품 마감 수량과 근거 |
| 촉매 마감 검토 | 촉매별 총량, 공장별 비율, 계산 후보, 조정, 최종 후보, ERP 차이·미정산 | 필요한 촉매 마감 수량 조정과 이유 |
| 선택 행 상세 | 원본 파일·시트·행, BOM 구성, 제외한 후속 이동, 적용 규칙 | 해당 범위의 수정 이유 확인·변경 |
| 확정·출력 | 남은 항목과 영향받는 출력, 이전 확정과의 차이 | 확정 또는 초안 출력 선택 |

예를 들어 세정 M28950-2J540을 선택하면 현대 아산·화성3 두 행에 제품 수량을 입력한다. 입력한 제품 수량으로 비율과 연결 촉매의 배분 후보가 함께 바뀐다. `제품 분할 수량`과 `촉매 마감 조정 수량`은 별도 칸으로 둔다. 지난달 경로 이름은 재사용하되 지난달 수량은 이번 달 값으로 자동 복사하지 않는다.

빈칸은 미입력, 0은 실제 수량 없음이다. 값을 바꾸면 영향받는 후보를 재계산하고 변경 전·후·사유를 보존한다. 재계산이 기존 사용자 조정을 조용히 덮어쓰지 않으며 새 원본과 충돌하면 해당 조정만 다시 검토한다. 미완료가 있으면 해당 계산·출력에 표시하고 월 전체를 확정한 것으로 표시하지 않는다. 다른 품목의 검토와 초안 저장은 계속할 수 있다.

**남은 설계 작업:** 실제 대표 품목을 넣은 화면 시안에서 입력 순서, 표 가독성, 근거 확인, 미입력·오류 상태를 검토한다. 시안의 색상·배치 및 UI 구현 기술은 아직 확정하지 않는다. 사용자가 별도 이미지를 준비해야만 다음 단계로 갈 수 있게 만들지 않는다.

### 13.4 결과 저장·출력 구조

한 월의 확정 버전에 원본 목록, 적용 BOM·경로·단가, 월별 입력, 계산 근거, 조정, 최종 명세, 미정산을 함께 보관하는 방식으로 제안한다. 확정 시점의 값과 버전을 모두 보존하여 최신 기준표를 다시 조회하지 않아도 같은 결과를 재출력할 수 있어야 한다.

| 출력 | 묶는 기준 | 반드시 연결할 내용 |
|---|---|---|
| 희성 공장별 자료 | 희성 촉매·해당 작성 양식의 공장 구분 | 같은 확정 버전의 마감 수량, 이월·당월 출하·미마감 근거 |
| 현대기아 입력용 | 촉매·세부 공장·필요한 단가 구분 | 울산1·3·5 등을 보존. ERP 통합처를 세부 공장 대신 쓰지 않음 |
| ERP 거래처별 자료 | 촉매·ERP 마감처·적용 단가 | 세부 공장 명세를 합산. 울산 세부 합계와 ERP 울산 합계 일치 |
| 미정산 내역 | 촉매·마감처·단가·사유 | 전월 미정산+당월 입고+확인된 조정−실제 마감의 연결 |
| 종합·누적 | 월·사업장·계획 버전·실적 확정 버전 | 같은 확정 이력으로 집계. 미확인 과거 월과 계획을 0으로 대체하지 않음 |

사용자가 확정 후 수정하면 기존 버전을 남기고 새 버전으로 재확정한다. 이전 버전으로 만든 엑셀도 해당 버전을 표시한다. 새 BOM·경로·단가를 가져와도 과거 확정값은 바뀌지 않는다. 지난달 재확정으로 다음 달 이월에 차이가 생기면 영향을 보여주고 다음 달 값을 조용히 덮어쓰지 않는다.

출력 엑셀은 결과 전달용이다. 출력 파일을 직접 수정한 값이 프로그램에 자동 반영된 것으로 간주하지 않는다. 수정 사항을 월 작업에 반영해 재확정·재출력하는 흐름을 사용한다. 출력 실패는 확정 데이터나 이전 출력물을 훼손하지 않아야 한다.

**남은 설계 작업:** 기존 실제 양식의 열과 저장할 명세를 연결하고, 동일 사례의 희성 공장별·ERP 통합·미정산 출력 견본을 대조한다. 화면 시안과 출력 견본까지 검토하기 전 네 항목 전체의 설계 완료를 선언하지 않는다.

### 16.3 입력·조정·검토 상태의 상세 설계

- 제품 분할 입력과 촉매 마감 수량 조정은 별도 작업이다. 제품 분할 변경은 비율 근거를 바꾸고, 촉매 조정은 계산 후보·변경 수량·차이·사유를 별도 기록한다. 직접 제품 분할이 필요한 범위에서만 입력을 요청한다.
- 빈칸은 미입력, 0은 수량 없음이다. 배분 근거 합계 0은 자동 균등 배분하지 않는다. 분할 입력칸의 음수·소수는 오류로 표시하고 반품은 원본 반품 내역과 별도 조정 절차로 연결한다.
- 분할 대상 전체 제품 수량이 원본에서 확인되면 입력 합계와 나란히 비교한다. 합계가 다르면 차이와 사유를 보존한다. 근거가 없는 합계에 맞추도록 임의 숫자를 채우지 않는다.
- 새 자료·BOM·경로·단가를 반영하면 영향을 받은 후보를 재계산한다. 이전 수동 조정은 조용히 덮어쓰지 않고 변경 전후를 비교한 후 해당 건만 재검토 상태로 둔다.
- 원본·총량·마감처 연결이 없는 건은 해당 계산과 출력에 미완료를 표시한다. 미완료 건이 있어도 다른 품목 검토·초안 저장은 가능하다. 차이가 없는 결과와 미완료 결과를 함께 월 확정으로 표시하지 않는다.
- 차이에 사유와 처리 근거가 확인된 경우와 원인 미확인 차이를 구분한다. 합계 0으로 맞추기만 해서는 검토 완료로 바뀌지 않는다. 검토자·시각·사유와 월 버전을 함께 보존한다.

이번 시안은 대표 사례로 입력 방식과 표 가독성을 검토하는 범위다. 전체 품번 목록, 실제 파일 가져오기, 촉매 수량 조정 창, 저장·확정 기능까지 구현한 것으로 보지 않는다. 시안의 입력 저장 표시는 대화 내 체험 상태만 유지하며 업무 자료를 변경하지 않는다.

### 16.4 확인 결과와 다음 설계

시안에서 단계 전환, 품번 근거 표시, 600:400의 720:480 배분, 미입력·0·음수·근거 미기재 상태, 출력별 합계를 확인했다. 1,024·736·360·320px 환경에서 화면 전체의 가로 넘침을 확인했으며, 좁은 화면의 표는 표 영역 안에서 가로로 조회한다. 넓은 화면·좁은 화면 및 입력 화면을 이미지로 확인했다. 이는 시안 동작 점검이며 실제 마감 계산 프로그램 검증이 아니다.

월별 입력·검토 화면 초안을 작성했으며 사용자 검토는 남아 있다. 다음은 **결과 저장·출력 구조를 실제 양식과 연결하는 상세 설계**다. 같은 확정 버전에서 희성 공장별 자료·ERP 거래처별 명세·미정산을 어떻게 묶고 대조할지, 초안/확정/재확정 이력을 어떻게 보관할지 구체화한다. 공유 촉매 일반 배분 총량 및 2JAV0 당시 자료 차이는 계속 열린 항목으로 관리하며, 화면 초안 완성을 이유로 구현 단계로 전환하지 않는다.

합계는 확정 명세에서 계산한다. 현대기아 울산1·3·5와 ERP 현대 울산을 모두 별도의 거래로 저장해 더하지 않는다. 동일 촉매라도 마감처·단가·귀속이 다르면 명세를 나누며, 같은 명세에 사용된 제품·경로 근거는 별도 연결한다. 계산 전 값·반올림 차이·사용자 조정·최종값을 구분하고 수량·금액의 계산 정밀도와 표시 단위도 보존한다.

원본 자료, 경로 관리 초안과 승인된 기준, 작업 초안, 확정본, 출력 파일의 역할을 구분한다. 검토용 경로 엑셀을 가져오는 것은 가능하지만 엑셀과 프로그램 양쪽을 독립적인 최신 기준으로 운영하지 않는다. 출력 엑셀을 밖에서 수정해도 확정본이 바뀐 것으로 보지 않는다. 변경값을 월 작업에 반영하고 재확정해야 새 공식 결과가 된다.

### 17.4 확정과 재확정 처리

1. 현재 초안이 참조하는 원본·기준·전월 이월과 마지막 성공 계산 결과가 일치하는지 확인한다. 계산 후 입력이 바뀌었으면 ‘재계산 필요’로 표시한다.
2. 미확인 귀속·총량 누락·분할 미입력·원인 미확인 차이 등 해당 월 확정을 막는 항목과, 근거가 확인된 미정산을 구분한다. 근거가 확인된 미정산은 잔여가 있다는 이유만으로 미완료로 취급하지 않는다.
3. 최종 명세·미정산·근거·변경 이력과 현재 확정본 지정을 하나의 저장 작업으로 완료한다. 일부만 저장된 확정본은 사용자에게 완료로 보이지 않아야 한다. 반복 클릭·재시도로 같은 확정본이 중복 생성되지 않게 한다.
4. 엑셀 출력은 저장된 확정본을 참조해 별도로 수행한다. 출력 실패 시 확정 데이터는 유지하고 같은 버전으로 재출력한다. 생성 중인 파일은 완성본 이름으로 표시하지 않으며 기존 파일을 덮어쓰지 않는다.
5. 확정 후 수정은 기존 확정본에서 새 초안을 만들고 변경한 항목만 재검토한다. 비교 화면은 촉매·공장·ERP 마감처·수량·단가·금액·미정산의 이전/새 값·차이·사유를 표시한다. 총합이 같더라도 공장 귀속이 바뀐 행을 생략하지 않는다.
6. 재확정 시 새 확정 차수를 만들고 이전 확정본에는 ‘이전 버전’ 표시를 붙인다. 이전 버전의 출력과 수치도 계속 조회한다. 잘못된 재확정을 되돌릴 때도 과거값을 바탕으로 새 수정 초안·재확정 이력을 남긴다.

확정본 재출력은 저장된 수량·금액을 사용하며 최신 계산기를 다시 돌리지 않는다. 과거와 정확히 동일한 파일이 필요하면 보관한 출력 파일을 제공한다. 새 양식으로 같은 확정값을 출력할 때는 양식 버전만 추가하고 재확정하지 않는다. 출력 양식에서 수량·금액을 다시 계산해 확정값과 달라지는 기능은 허용하지 않는다.

### 17.5 지난달 수정이 다음 달에 미치는 영향

다음 달 초안을 만들 때 전월의 어떤 확정본을 이월 근거로 사용했는지 고정한다. 전월 재확정이 생기면 미정산을 촉매·마감처·단가 등 귀속 단위로 비교한다. 전체 합계만 같아도 귀속이 바뀌었으면 영향이 있는 것으로 처리한다.

| 다음 달 상태 | 처리 |
|---|---|
| 작업을 시작하지 않음 | 새 초안을 만들 때 전월 현재 확정본 사용 |
| 작업 중 | 전월 변경 알림과 행별 이월 차이 표시. ‘새 이월 반영’ 시 초안에서 재계산하고 관련 수동 조정만 재검토 |
| 이미 확정 | 해당 확정본 보존. ‘전월 변경 영향 미처리’ 표시 후 수정 초안을 만들어 영향 검토·필요 시 재확정 |

‘확정’ 상태와 ‘선행 월 변경 영향’ 상태를 따로 관리한다. 전월을 재확정했다고 다음 달을 자동으로 해제하거나 덮어쓰지 않는다. 작업 중인 다음 달을 새로 확정하려면 남은 전월 변경 영향 처리가 필요하다. 다음 달 재확정으로 그다음 달 이월도 달라지면 같은 방식으로 연결해서 표시하며, 월을 건너뛰어 임의 조정값을 넣지 않는다. 이월 수치·귀속에 영향이 없는 문구 수정은 다음 달 수량 재검토를 유발하지 않는다.

**가정 예시:** 9월 글로비스 전체 미정산은 450개다(18절에서 미입고 449개 외 전월 잔여 1개를 포함해 정정). 나중에 새로운 근거로 재확정한 값이 가령 451개라면 10월에는 이월 +1개의 발생 품목·사유를 보여준다. 451은 저장 동작을 설명하기 위한 가정이며 실제 수정값이 아니다. 기존 10월 확정 수량을 자동으로 1개 바꾸거나, 차이를 일반 공장에 배분하지 않는다.

### 17.7 보관·백업·프로그램 업데이트

업무 보관 위치는 사용자가 지정하는 한 자료 폴더를 기본으로 하고, 그 안에 원본 보관·작업/확정 데이터·출력 보관을 구분한다. 파일 위치는 보관소 기준 상대 위치와 파일 ID로 연결해 PC를 바꿔도 재연결할 수 있게 한다. Git 저장소에는 코드·설계만 두며 업무 원본과 확정 데이터는 넣지 않는다.

- 월 확정·재확정 후 및 저장 구조 업데이트 전에는 데이터베이스·연결된 원본·출력·기준자료와 파일 목록을 함께 복구할 수 있는 백업을 만든다. 일반 비밀정보/API 키는 업무 이력·출력에 포함하지 않는다.
- 파일 복사·해시 확인이 끝나기 전 원본 등록을 완료로 표시하지 않는다. 데이터베이스만 복사하고 원본·출력이 누락된 것을 완전한 백업으로 표시하지 않는다. 임시 파일과 완성된 백업을 구분한다.
- 같은 디스크의 백업은 수정 실수 복구용이다. PC 변경·디스크 장애에 대비해 지정한 다른 저장 위치로 백업 묶음을 복사할 수 있게 한다. 저장 위치나 자동 삭제 기간은 임의로 지정하지 않으며 확정 이력 자동 삭제 기능은 기본 범위에 두지 않는다.
- 프로그램 업데이트로 저장 항목이 바뀌면 기존 자료의 복사본에서 변환·확정 합계·이월 연결을 먼저 검사한다. 실패 시 기존 자료를 유지한다. 변환된 자료를 구버전 프로그램으로 무조건 열 수 있다고 보장하지 않는다.
- 복구는 별도 위치에서 백업 구성·해시·월별 확정 수치·원본 연결을 확인한 다음 사용 자료로 전환한다. 원래 자료를 바로 덮어쓰지 않는다.

과거 결과 재출력은 저장된 확정값으로 보장한다. 과거 알고리즘으로 다시 실행하는 것은 별도 기능이며 해당 규칙·프로그램과 실행 환경 보존이 필요하므로, 버전 번호만 남기면 언제나 과거 계산을 그대로 실행할 수 있다고 약속하지 않는다.

### 17.8 구현 시 확인할 동작과 남은 범위

다음은 향후 구현의 검증 기준이며 현재 프로그램 테스트를 실행했다는 뜻이 아니다.

3. 수정 초안은 기존 확정본을 변경하지 않으며 재확정 전후 수량·금액·세부 귀속 차이가 보인다.
4. 전월 재확정 시 다음 달의 품목별 이월 영향을 표시하고, 확정된 후속 월은 자동으로 변경하지 않는다.

6. 동일 촉매의 여러 제품 근거, 여러 세부 공장, 서로 다른 단가가 명세와 집계에서 누락·중복되지 않는다.
7. 출력 양식만 바꾼 재출력과 수량을 바꾼 재확정을 구분한다. 누적에는 월별 확정본 하나만 포함한다.
8. 백업을 새 위치에 복구해 원본·확정 명세·출력 파일·전월 연결을 확인한다. 저장 구조 변경 전후에도 확정 합계가 보존된다.

### 20.3 기본 자동 계산과 월별 수정

1. 제품 수량×BOM 소요량을 경로·세부 공장별로 집계해 기본 비율을 계산한다. 촉매 총량을 제품마다 중복 배분하지 않는다.

3. 공장별 합계를 마감 대상 총량과 대조한다. 한 공장의 수정으로 남은 수량을 다른 공장에 조용히 넘기지 않는다. 미정산이나 총량 변경이 필요한 경우는 그 원본·사유와 연결하는 별도 조정이다. 월별 수정만으로 총량 근거를 우회하지 않는다.

6. 월별 수정은 기준 경로·BOM·다음 달 자동값에 적용하지 않는다. 지속되는 변경은 기준표 변경으로 따로 관리한다. 저장·재확정에는 기존 17절의 버전·변경 이력을 적용한다.

### 21.4 계산 순서 설계안

1. **자료 범위 확인:** 대상 월·조회 범위·파일 개정과 촉매별 원문 행을 확인한다. 자료에 행이 없다는 것과 0을 구분하고, 전월 어떤 확정본을 사용했는지 고정한다.
2. **이월·입고 정합:** 촉매사 기준과 우리 장부 기준을 각각 계산한다. 같은 수량을 양쪽에서 중복 가져오지 않는다. 차이가 있으면 입고·반품·월말 추가분·수정본 등 근거를 연결한다. 차액을 자동 조정으로 만들지 않는다. 적용한 수량·자료 버전·보완 근거를 계산 입력에 보관한다.
3. **이번 달 보류·해소 반영:** 전월 보류가 계속되는 부분, 이번 달 해소된 부분, 새로 보류할 부분을 연결한다. 전월 미정산 전부를 가용량에서 다시 빼거나, 과거 보류 품번을 앞으로 항상 제외하지 않는다. 예정 월 도달만으로 자동 해소하지 않는다.
4. **실제 입고·별도 귀속 처리:** 글로비스 실제 입고 수량을 BOM으로 계산하고 촉매별 직사급 예외를 분리한다. 글로비스 미입고 잔여는 해당 귀속으로 보존한다. 실제 입고가 계산상 가용량을 넘으면 잘라 맞추지 않고 이월·입고·구성 차이를 확인한다.
5. **배분 대상군 생성:** 적용 가용량−이번 달 남길 보류 수량−글로비스 실제 마감−별도로 귀속 확정한 마감으로 일반 대상군을 만든다. 같은 촉매라도 공급업체·단가·귀속상 구분이 필요한 수량은 근거 없이 합치지 않는다. 음수 잔여는 자동 0 처리하지 않는다.
6. **기본 배분·월별 수정:** 다중 일반 마감처는 제품×BOM 비율로 계산한다. 단일 귀속 및 유미코아에서 이미 구분된 명세는 해당 처리 흐름을 유지한다. 사용자가 확인한 월별 예외는 자동값과 별도로 수정·사유를 남긴다. ERP 지역 합계는 세부 공장 명세에서 계산한다.
7. **확정 전 수량 검산:** 적용 가용량=실제 마감+월말 미정산을 해당 귀속 단위에서 확인한다. 보류 사유, 수정 사유, 미입력 분할, 원천 차이가 해결되지 않은 명세는 확정하지 않는다. 다른 품목의 검토·초안 저장은 가능하다.

화면의 마감 대상 총량은 원천·보류·별도 귀속으로 계산한 읽기 전용 결과다. 원천 오류를 고칠 때는 해당 근거·수량을 보완하고 재계산한다. 이유 없이 총량 숫자 하나를 바꾸는 입력칸은 두지 않는다. 제품 분할과 최종 촉매 수정도 같은 칸으로 합치지 않는다.

월별 수정은 입력 완료 단위로 저장하고 변경 전 자동값·최종값·사유를 남긴다. 취소하면 이번 입력 이전 상태로 돌아가며, ‘자동 계산값 사용’은 그달 수정값을 해제하는 별도 동작이다. 자료 교체·기준 변경으로 재계산할 때 기존 입력을 삭제하지 않고 영향받은 항목만 재검토 표시한다. 같은 숫자라도 근거 파일이 바뀌었으면 적용 관계를 확인한다.

### 22.4 처리 목록을 만드는 기준

검토 목록에는 문제의 원인, 영향받는 품번·경로·출력, 필요한 다음 행동과 근거를 함께 표시한다. 같은 파일 범위 문제 때문에 여러 촉매에 차이가 생겼다면 한 자료 문제 아래 영향 품목을 묶는다. 하나의 원인을 품목 수만큼 중복 질문하지 않는다.

| 표시 상태 | 뜻 | 예시 행동 |
|---|---|---|
| 자료 필요 | 해당 계산에 필요한 파일·행·기간 또는 근거가 없음 | 필요한 자료 역할·조회 범위 확인 |
| 입력 필요 | 승인된 처리 방식에 필요한 그달 값이 비어 있음 | 해당 제품의 공장별 분할 입력 |
| 차이 처리 필요 | 원천·귀속·단가·수량 차이의 적용 방법이 정해지지 않음 | 원본 위치와 양쪽 수량을 보고 근거 선택·보완 |
| 재계산 필요 | 계산 후 자료·기준·입력이 바뀜 | 영향을 받은 후보 재계산 |
| 수정 재검토 | 재계산으로 기존 월별 예외의 근거가 바뀜 | 자동값·유지된 수정값·차이를 확인 |
| 미정산 보관 | 귀속·잔여·처리 근거가 연결된 미정산 | 그달 해소분이 있는 경우에만 처리 |
| 확인 완료 | 해당 항목의 필수 입력과 계산·대조가 완료됨 | 근거 열람 가능. 반복 수동 승인 요구하지 않음 |

과거 비율과의 차이는 별도의 비교 정보다. 그 자체를 ‘차이 처리 필요’로 만들어 새 월 확정을 막지 않는다. 다만 새 월의 원천 차이·입력 누락은 과거 예외가 있었다는 설명으로 생략하지 않는다. 사용자 확인이 필요하지 않은 자료 대조는 Codex 또는 향후 프로그램에서 먼저 수행한다.

이전 단계의 원천 154품목 전체와 그달 처리 목록은 다르다. 그달 거래·계산 대상, 이월 잔여, 필요한 직접 입력으로 작업 범위를 만들고, 원천의 비활성0행은 열람할 수 있도록 보존한다. 월계획이 없거나 단산이라는 이유로 실제 거래·잔여를 제외하지 않는다. 과거 이관값과 새로 계산할 명세도 구분한다.

과거 이관 미정산 중 사유 공란인 값은 출처·귀속·잔여와 ‘과거 사유 미기재’를 보존한다. 이관된 잔여를 그대로 연결하는 것과 새 보류를 사유 없이 만드는 것을 구분한다. 해당 잔여를 해소·변경할 때는 그달 처리 근거를 추가한다. 원문에 없던 과거 사유를 임의 생성하지 않는다.

### 22.7 현재 설계 상태와 다음 범위

경로·계산·월별 입력/검토·이력/출력의 네 설계안을 월 작업 흐름으로 연결했다. 사용자에게 매월 요구할 입력과 프로그램의 자동 처리, 품목별 미완료와 전체 확정 조건을 구체화했다. **이로써 모든 업무 자료 차이가 해결됐거나 최종 UI가 승인됐다는 뜻은 아니다.** 기존 화면 시안은 수정하지 않았으며 글로비스 잔여450 표시 반영 등의 후속 항목을 유지한다.

## 23. 촉매사 기말적송재고 PDF와 수정값 적용 (2026-10-13)

### 23.2 원본·수정·적용값

- 기본 적용값은 해당 공급업체·촉매·기준월에 연결된 PDF 수량이다. 희성 가공본, 유미코아 Summary, 자체 전월 확정 이월은 비교 대상으로 유지하며 PDF 값에 더하지 않는다. 서로 다르면 양쪽 값과 출처를 표시하고 채택 근거를 남긴다.
- 화면은 `품번 / PDF 원본값 / 사용자 수정값 / 최종 적용값 / 수정 사유 / 대조 차이`를 보여준다. 수정값 공란이면 원본값, 0이면 명시적 0을 적용한다. 수정은 원본값에 가산하는 값이 아니라 대체할 최종 이월 수량이다. 입력을 지우면 검증된 PDF 값으로 복귀한다.
- 인식 오류 정정과 업무상 수량 조정을 구분한다. 인식 오류는 원본 이미지와 추출값·정정값을 함께 남기고, 업무 조정은 원본 수량·변경 전후·사유·근거·작업자·시각을 기록한다. 원본 PDF와 기존 확정값은 수정하지 않는다.
- 수정은 해당 월·공급업체·촉매·필요한 귀속 범위에만 적용한다. 이월 수정과 공장별 배분 수정은 별도 입력이다. 이월 변경 시 가용량·배분·잔여를 재계산하고 영향을 받는 기존 공장별 수정은 재검토 상태로 둔다. 다른 공장에 차액을 자동 전가하지 않는다.
- 전월 확정본은 비교값으로 보존한다. PDF 채택이나 당월 수정으로 전월 확정본을 소급 변경하지 않는다. 당월 확정 결과가 다음 달 참조로 이어지며 재확정 시에는 기존 17절의 다음 달 영향 절차를 적용한다.
- PDF 교체 시 기존 수정·사유를 삭제하거나 새 원본에 무조건 적용하지 않는다. 바뀐 품번·수량·기준월을 표시하고 해당 수정의 유효성을 재검토한다. 동일 파일 재등록으로 이월을 중복 생성하지 않는다.

### 23.3 PDF 인식·검산과 계산 연결

1. 원본 파일·해시·공급업체·재고 기준월·적용 마감월과 페이지·표 행/영역을 보관한다. 텍스트 PDF는 텍스트 추출, 스캔 PDF는 OCR 또는 이미지 인식으로 품번·양쪽 수량·차이·사유를 읽는다. 인식 방식과 버전을 남긴다.
2. 품번의 O/0·I/1, 쉼표·부호·빈칸과 행 정렬을 검사한다. 합계 행은 품목 수량에 더하지 않는다. 누락 품번·인식 실패·자료에 없는 행을 0으로 채우지 않는다. 원본에서 필요한 행을 수동 보완할 수 있게 한다.
3. 희성은 품번 합계와 양쪽 합계·차이를 검산한다. 유미코아는 행별 및 총계의 `전월말 + 공급 − 마감 = 당월말`을 검산한다. 합계 일치만으로 품번 인식이 모두 맞다고 간주하지 않는다. 불명확한 행만 원본 이미지와 함께 검토 대상으로 모은다.
4. `희성 적용 전월 이월 + 당월 출하`로 가용량을 계산한 뒤 기존 글로비스·보류·공장 배분 순서를 따른다. PDF의 사유를 보존하되 `9월 마감 예정` 같은 문구만으로 보류가 자동 해소됐다고 처리하지 않는다.
5. 유미코아 PDF의 기말 적송은 다음 달 기초 이월의 기본 출처이며 Summary의 기존 공장 구분을 다시 배분하는 근거가 아니다. 동일 월 출하·마감 값을 PDF와 Summary에서 중복 합산하지 않는다.
6. 원본 인식 문제, 수정 사유 누락, 출처 간 미해결 차이 또는 수량 균형 오류는 영향 명세에 표시한다. 다른 품목 검토·초안 저장은 허용하되 필요한 문제 해결 전 전체 월 확정을 완료로 표시하지 않는다.

인수 기준은 ① 두 PDF의 재고 기준월/적용월 구분, ② 희성 10,953·유미코아 610 원본 합계 검산, ③ 공란·0·수정값·원본 복귀 구분, ④ 수정 이력과 원본 보존, ⑤ PDF 재등록·Summary 중복 합산 방지, ⑥ 원본 교체 시 수정 재검토, ⑦ 이월 수정 후 가용량과 배분 재계산이다. 이는 향후 구현 검증 기준이며 현재 자동 인식 테스트가 통과했다는 뜻은 아니다.
