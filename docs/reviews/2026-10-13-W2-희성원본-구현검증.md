# W2.1 희성 원본 등록·읽기 구현 검증

2026-10-13. W2 전체 중 **원본 보관·선택 기반, 희성 출하 XLSX, 희성 적송재고 PDF의 보조 인식·정정**을 구현했습니다. ERP·제품/반제품 수불·유미코아·글로비스 어댑터는 아직 구현 전입니다. 마감 배분·확정·엑셀 출력도 후속 단계입니다.

## 구현한 흐름

1. 월 작업을 열고 희성 출하 또는 전월 적송재고 역할을 선택합니다. 출하는 당월, 적송재고는 전월로 기준월을 연결합니다.
2. 원본 파일을 선택하면 임시 복사·SHA-256 검증·원본 보관 후 DB에 등록합니다. 원본 Excel/PDF를 수정하지 않습니다.
3. 등록 목록에서 원문 행·수량·셀 또는 PDF 이미지 근거와 확인 항목을 봅니다.
4. 읽기 검산이 완료된 후보를 명시적으로 ‘이번 달 원본으로 사용’합니다. 등록만으로 이전 자료를 교체하지 않습니다.
5. 수정본을 채택하면 이전 원본·명세·채택 이력을 보존합니다. 한 역할에는 한 후보만 채택하며 두 수정본의 수량을 합산하지 않습니다.

동일 파일·월·역할·기준월·읽기 버전으로 재등록하면 기존 결과를 반환하고 초안 개정과 수량을 중복 추가하지 않습니다. OCR 언어 설치 또는 읽기 기능 변경 뒤에는 ‘원본 다시 읽기 · 새 후보’로 보관 파일을 다시 읽을 수 있습니다. 이전 채택본은 자동 교체하지 않습니다.

## 희성 출하 읽기

시트명이나 열 문자 대신 `자동차품번`, `출하`, `년월` 헤더로 표를 찾습니다. 제목 행과 열 위치가 바뀌어도 헤더가 유일하면 읽고, 후보 표가 여러 개이거나 필수 열이 모호하면 확인 필요로 남깁니다. 년월은 파일명이 아닌 원문 행에서 대조합니다.

품번, 숫자·부호, 원문 수식과 저장 결과, 시트·행·셀을 보존합니다. 빈 수량·Excel 오류·미계산 수식은 0으로 대체하지 않습니다. 같은 품번의 원문 행을 모두 보관하고 Decimal로 합계만 집계합니다. 출하 합계가 있으면 행별 수량과 대조합니다. 이 결과를 실제 마감 수량으로 표시하거나 배분하지 않습니다.

실제 `9월 우신공업 출하실적.xlsx`를 별도 임시 보관소에서 등록하여 70행·70품번·141,262개를 원본과 전건 대조했습니다. 음수 출하 −4·−4·−3도 보존했습니다. 원본과 보관 사본의 바이트가 같고 원본 해시가 유지되는 것을 확인했습니다.

## 희성 적송재고 PDF

현재는 제공된 **1페이지·테두리 표 양식**을 대상으로 로컬 PDF 렌더링과 Windows OCR을 사용합니다. 외부 AI API나 OpenRouter로 파일을 보내지 않으며 API 키가 필요하지 않습니다. Windows 사용자 언어의 OCR 기능이 없거나 표 형태가 다르면 원본은 보관하되 확인 필요로 남깁니다. 범용 PDF 해석 기능으로 표현하지 않습니다.

인식 후보에는 원문 문자열, 페이지·행 영역, OCR 품번·수량, 상대측 수량과 사유를 남깁니다. 사용자는 원본 행 이미지를 보며 품번·희성 수량·우신 수량을 정정하고 행 확인을 표시합니다. 본문의 재고 기준월, PDF에 표시된 합계와 확인 내용을 입력합니다. 미확인 행·중복 품번·수량 차이·합계 차이가 남으면 채택하지 못합니다.

실제 PDF 시험 결과는 다음과 같습니다.

- 8월 말 희성 PDF에서 34행과 본문 기준월 2026-08을 식별했습니다.
- OCR만으로는 품번 일부와 한 자리 수량을 놓쳤으며, 읽힌 수량 합계는 10,924개였습니다. **10,953개를 완전 자동 인식한 결과가 아닙니다.**
- 원본 이미지에서 확인한 34행 값으로 정정한 뒤 합계 10,953개, 양쪽 수량 일치, 기준월 확인을 검산했습니다.
- Edge 화면에서 정정 저장·채택·새로고침 후 복원, 원본 행 이미지 표시를 확인했습니다.

원문 추출 행은 수정하지 않고 별도 인식 정정 이력을 저장합니다. 이미 채택한 결과를 다시 정정하면 별도 후보를 만들어 기존 채택본을 유지합니다. 이번 입력은 **인식 오류 정정**이며, 업무상 이월 수량을 바꾸는 가산·대체 조정 기능은 아직 아닙니다. PDF와 ERP 이월 구성 차이의 판단도 후속 단계에서 연결합니다.

## W1 결함 수정과 입력 보존

- 다른 월·최신 저장본 읽기 동안 메모 편집을 잠급니다. 메모 자동 저장 중에는 계속 입력할 수 있는 기존 동작을 유지합니다.
- 세션 연결 성공 후 월 목록만 실패해도 ‘다시 연결’이 표시됩니다. 실패한 목록을 정상적인 0건으로 안내하지 않습니다.
- PDF 정정 입력 중에는 다른 원본 선택과 월 전환을 막고 저장 또는 입력 취소로 이어갑니다. 브라우저를 닫을 때도 미저장 입력을 감지합니다.
- 원본 등록·정정·선택은 예상 초안 개정을 검사합니다. 다른 창의 최신 변경을 오래된 화면에서 덮어쓰지 않습니다.

## 저장 구조와 복구

DB 버전은 2입니다. 버전 1 DB는 SQLite 백업 API로 `backups/before-schema-2-*.sqlite`를 만든 뒤 트랜잭션으로 변환합니다. 기존 월·메모·이력은 보존합니다. 실제 이관 DB는 이번 테스트에 사용하거나 변환하지 않았습니다.

원본 파일, 등록 배치, 추출 행, 인식 정정 이력, 채택 원본, 채택 변경 이력을 분리했습니다. 등록 저장 실패 시 DB는 롤백하고 이전 채택본을 유지합니다. 먼저 복사된 미연결 파일은 재시도 때 해시를 확인해 재사용합니다. 원본 다운로드·채택 전에도 보관 파일 해시를 검사합니다.

## 이어서 할 일

다음은 W2의 나머지 자료 어댑터입니다. ERP 입고와 제품·반제품 수불부터 연결하고, 이어서 유미코아·글로비스 자료를 읽습니다. PDF OCR 정확도 개선과 양식 변경 시 열/표를 지정하는 보완 방식도 남아 있습니다. 현재 확인 필요 자료를 임의 계산으로 통과시키지 않으며 W2 전체 완료 또는 자동 마감 완료로 표시하지 않습니다.
