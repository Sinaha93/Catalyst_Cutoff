# 코드와 업무 설계 리뷰

검토일: 2026-10-13. 기준 커밋: `9b44012`.

## 판단

현재 구현은 W1 월 작업·메모 저장 기반입니다. 실제 마감 업무에 쓰는 계산·확정·엑셀 출력 프로그램은 아직 아닙니다. 이 경계는 README와 화면에 표시되어 있습니다. DB 저장과 감사 이력의 원자성, 개정 충돌 검사, 같은 월 재사용, 중복 실행 차단은 구현과 테스트에서 확인했습니다.

업무 설계는 원천 대조, 제품×BOM 기여, 글로비스·직사급 예외, 월별 수정, 확정 이력의 책임을 나누어 놓았습니다. 기존 9월 결과의 일치와 신규 원본부터의 자동 산출을 구분한 점도 적절합니다. 다음 개발은 W2 원본 보관·읽기이며, W1의 아래 화면 결함은 별도로 수정할 필요가 있습니다.

## 수정이 필요한 코드

### 1. [P2] 다른 월 또는 최신본을 불러오는 동안 입력한 메모가 사라집니다

위치: `frontend/src/main.tsx` 62~76행, 93행.

`openMonth()`와 `reloadDraft()`는 읽기 요청 전에 현재 입력 상태를 검사하거나 확인을 받지만, 요청 중 textarea는 계속 편집 가능합니다. 응답이 돌아오면 `adopt()`가 `setNote(d.note)`를 실행합니다. 그 사이 사용자가 입력한 글을 검사하지 않고 서버 메모로 교체합니다. 서버가 느린 경우 다른 월을 여는 동안 기존 월에 추가한 메모도 같은 방식으로 유실됩니다.

재현: 저장된 월을 연 상태에서 다른 월 읽기 또는 최신본 읽기 응답을 지연 → 읽기 중 현재 메모 입력 → 응답 완료. 입력이 응답의 저장 메모로 대체됩니다. 실제 코드의 두 핸들러를 추출해 지연 API와 실행하는 격리 검사에서 두 경우 모두 재현했습니다. 전체 브라우저 검증은 아닙니다.

수정 방향: 읽기·월 전환 동안 편집을 잠그거나, 요청 시점 입력 개정과 현재 개정을 비교해 새 입력을 보존합니다. 단순히 모든 `busy`에 textarea를 잠그면 자동 저장 중 입력 흐름도 끊길 수 있으므로 ‘읽기/전환’과 ‘저장’ 상태를 구분하는 편이 좋습니다. 저장 요청 중 이어서 입력한 메모는 현재 로직의 장점이므로 보존해야 합니다.

필요 검증: 다른 월 읽기 및 최신본 읽기의 지연·실패, 읽기 중 입력, 저장 중 연속 입력. 기존 브라우저 테스트는 이 읽기 중 입력 시나리오를 포함하지 않습니다.

### 2. [P2] 세션 성공 후 월 목록 조회가 실패하면 화면에 재시도 버튼이 없습니다

위치: `frontend/src/main.tsx` 26~32행, 90행.

`load()`가 `/session` 성공 직후 session을 설정합니다. 다음 `/months` 호출이 일시적으로 실패하면 오류는 표시되지만 ‘다시 연결’ 버튼은 `!session`일 때만 보입니다. 이 상태에는 아직 선택한 초안도 없어 ‘최신 저장본 불러오기’도 없습니다. 사용자가 보관한 월 목록을 화면에서 다시 조회하려면 브라우저를 새로고침해야 합니다. 오류 코드와 빈 목록만으로는 저장된 자료가 없는 것처럼 오해할 수 있습니다.

재현: `/session`은 성공하고 `/months`만 실패하도록 실제 `load()`를 실행. session은 설정되고 오류도 남지만 재시도 버튼 표시 조건은 false입니다. 현재 코드의 함수 수준 검사와 표시 조건 대조로 확인했습니다.

수정 방향: 초기 조회 실패를 별도 상태로 두고 세션 존재 여부와 무관하게 목록 재시도를 제공합니다. 목록 조회 실패와 정상적인 0건을 다른 문구로 표시합니다.

필요 검증: 최초 목록 503 → 재시도 성공 → 기존 월 목록·선택 복원. 목록 실패를 정상적인 빈 목록으로 표시하지 않아야 합니다.

이번 요청은 리뷰와 프로세스 문서 작성이므로 제품 코드를 수정하지 않았습니다.

## 문서의 혼동과 이번 정리

운영 설계 첫머리에는 ‘다음 W1·구현 전’, 상세 설계 첫머리에는 ‘아직 미구현’이라는 최신 상태처럼 보이는 설명이 남아 있었지만 README와 실제 코드는 W1 완료·다음 W2입니다. 이번에는 두 문서 상단과 상세 설계의 진행 안내에 최신 상태를 표시했습니다. 절별 과거 검토 기록은 당시 상태로 보존합니다.

새 [업무 프로세스](../process/촉매마감-업무프로세스.md)는 처음 읽는 사람이 물류와 정산을 구분하도록 구성했습니다. 실물 흐름, 용어, 입력 자료, 단계별 완료 결과, 총량·배분 계산, 예외, 확정 조건과 출력 역할을 한 문서에서 설명합니다. 설명용 가정 숫자와 실제 9월 대조 기준은 분리했습니다.

다른 PC에서 작성한 운영 설계 23절의 적송재고 PDF 기준은 21·22절과 구현 계획의 입력에서 함께 사용합니다. 전월 확정 이월과 PDF 기본 이월을 더하거나, 한쪽 출처 구성만 교체해 중복을 만드는 처리로 설명하지 않았습니다. 일반 배분 후보와 월별 실제 마감 수정도 구분합니다.

후속 개발의 우선순위는 다음과 같습니다.

1. W1 읽기 중 메모 유실과 초기 목록 재시도 문제 수정.
2. 별도 이관한 실제 원본과 문서의 자료 버전 대조.
3. W2 역할·기간·원본 보관·수정본·PDF 추출과 품번별 검산.
4. W3 경로·BOM·단가·과거 이관의 승인 및 미확인 상태 연결.
5. W4 이후 계산·예외 검토·확정·출력의 업무 사례 검증.

미확인 원천 전표·유보 경로·현대기아 등록 규격을 모두 사용자에게 한꺼번에 질문하지 않습니다. 확인된 규칙과 미완료 표시부터 구현하며 자료로 결정할 수 없는 판단만 구체적으로 확인합니다.
