# 업무 보고서 출력 보완 — 개발 기록

사용자가 기존 계산 명세를 처음 목표한 업무 보고서까지 완성하도록 요청한 범위입니다. 사용자용 가이드는 UI 확정 후 별도로 작성합니다.

## 출력 범위

- 종합: 거래처별 전월 미마감, 당월 적용 수량, 마감 수량·금액, 다음 달 미마감 수량·금액.
- 거래처별 계산서: 기존 번호·품번·단가·수량·금액·공급업체에 단가 구분과 상세 공장을 표시합니다.
- 희성 마감자료: 출하 원본 다음에 기존 공장 순서의 가로형 표를 배치합니다. 구분되지 않은 위아 서산2는 디젤·카파로 추정하지 않고 별도 열로 표시합니다.
- 공장별 마감: ERP 지역 마감처와 상세 공장, 자동 수량과 적용 수량을 구분합니다.
- 미마감 내역: 전월 잔여·당월 추가·전월분 마감·차월 잔여와 단가별 금액을 표시합니다. 전월 잔여를 전부 정산한 행도 보존합니다.
- 계획 대비, 월별 수량·금액 그래프, 누적 실적, 직전 3·6·12개월 및 전년도 월평균을 포함합니다.
- 기존 희성·유미코아 명세, ERP 검토, 미정산 이월, 수량 검산, 수정 이력, 원본 해시는 추적용으로 유지합니다. 유미코아는 Summary 원문 표시값도 별도 보존합니다.

## 값과 버전의 의미

보고서 양식 버전은 `monthly-business-report-2`입니다. 단가를 최신 자료로 다시 조회하거나 수량을 재배분하지 않습니다. 거래처 계산서 금액은 이미 원 단위 반올림된 상세 공장 금액의 합계입니다. 출력 엑셀은 확정값 보관용이며 외부 편집이 프로그램 확정본을 변경하지 않습니다.

종합의 **당월 적용 수량(역산)**은 `마감 + 다음 달 미마감 − 전월 미마감`입니다. ERP 원본 입고 열로 위장하지 않으며, 품목별 실제 채택 이월·입고는 수량 검산에서 확인합니다. 계획은 채택된 계획 원본의 거래처별 행만 합산하고 공급업체별 중복 표를 더하지 않습니다. 미등록 계획과 0 계획은 구분하며 유효한 분모가 없으면 달성률을 비웁니다.

확정 시 `report_context`에 과거 보고서의 누적 행·파일 해시와 월별 선택 확정본을 저장합니다. 월마다 한 확정본만 사용하고, 전월 이월을 특정 버전에 연결했다면 그 버전을 존중합니다. 이전 확정본에는 확정 시점 이전 버전만 조회하는 호환 경로를 사용합니다. 해당 월의 프로그램 확정본은 과거 보고서의 같은 월 실적·계획을 함께 대체하므로 중복되지 않습니다. 이후 재확정·계획 변경은 과거 출력의 누적 조합을 바꾸지 않습니다.

과거 기준은 채택 보고서의 `종합3(누적)` 여섯 열입니다. 누락·중복 키·소수인 실적 수량은 미확인으로 구분하며 입고 자료로 대체하지 않습니다. 평균에 필요한 월이 하나라도 미확인이면 해당 평균을 산출하지 않고 확인 월수를 표시합니다. 과거 원문 값·행 위치·제외 이유는 동결 근거와 출력 안내에 남습니다. 그래프도 미확인 월을 0으로 그리지 않습니다.

ERP·현대기아 시스템의 자동 업로드 형식 인증은 포함하지 않습니다. 원본 업무 파일은 수정하지 않으며 엑셀·화면 캡처·시험 DB는 Git 저장소 밖에 보관합니다.

## 검증

- 백엔드 전체 203개 테스트 통과.
- 추가 보고서 검증: 월별 버전 중복·미래 버전 제외, 고정한 전월 버전, 과거 중복·누락·소수 수량, 실제 마감 기준 평균, 계획 중복 제외, 원 단위 반올림 보존, 글로비스·서산2 분리, 안전한 시트 이름.
- 프런트엔드 빌드 및 통합 브라우저 시험 통과: 저장·확정·엑셀 다운로드·재확정·이전 버전 보존.
- 실제 자료의 시험 확정본에서 거래처별 계산서·종합·미마감·희성 가로표·누적의 수량 및 금액 합계를 독립 대조했습니다. 연습으로 입력한 조정값도 보존했습니다.
- 종합·평균·거래처 계산서·희성 가로표·미마감·그래프를 이미지로 확인하고 숫자 표시, 범례, 줄바꿈을 보완했습니다.

진입점은 `backend/application/reporting.py`(동결·집계), `backend/adapters/business_workbook.py`(업무 양식), `backend/application/exports.py`(출력 검증·보관)입니다. DB 스키마 변경은 없습니다.

## 사용자 지정 종합 양식으로 정정 — 양식 v3

위 v2 종합표는 사용자가 제시한 원래 양식과 달랐습니다. `monthly-business-report-3`에서 원본처럼 한 표에 번호·거래처, 전월 미결/당월 입고/계산서/당월 미결의 수량·금액, 기간별 평균과 TOTAL을 배치했습니다. 회색·청색 병합 머리글, 검정 격자, 회색 합계행을 적용합니다. 금액 셀은 원화 값을 보존하고 원본의 `#,###,` 형식으로 천원 단위를 표시합니다. 틀 고정은 모든 출력에서 사용하지 않습니다.

원본 파일의 `종합!F7=H7+J7-D7`, `G7=I7+K7-E7`을 재확인했습니다. 기존 양식의 입고도 역산값이므로 역산 방식 자체가 잘못됐다는 이전 설명은 정정합니다. 동일 산식을 수량·금액에 각각 사용합니다. 전월 미결 금액은 연결된 전월 확정본의 잔여 장부금액, 최초 이관 월은 수량이 일치하는 기존 보고서의 전월 미결 금액을 사용합니다. 현재 단가로 전월 금액을 재평가하지 않습니다. 근거가 없으면 전월·입고 금액은 미확인입니다.

전월 금액 근거는 새 확정본의 `report_context.opening_summary`에 동결합니다. 구버전 확정본 재출력은 해시가 일치하는 채택 원본에서 읽습니다. 계획 대비는 별도 시트로 옮기고, 종합표의 계산 설명·미확인 사유는 `종합 연결 근거`에 둡니다. 평균의 원본 머리글은 유지하되 기존 합의인 마감 실적 기준과 누락 월 처리 원칙은 변경하지 않습니다. 과거 수치를 복사해 현재 확정값을 덮어쓰지 않습니다.

## 원본 혼합 그래프 복원 — 양식 v4

`monthly-business-report-4`는 기존 종합 수량·금액 선 그래프 2개를 원본의 혼합 그래프 1개로 바꾸고, 거래처별 계산서 10개 시트 오른쪽에도 각각 혼합 그래프를 출력합니다. 계획 수량은 하늘색 막대, 실적 수량은 노란색 막대, 계획 금액은 빨간 선, 실적 금액은 연두 선, 전년도 평균 금액·수량은 금색·보라색 점선입니다. 수량 축과 천원 표시 금액 축을 분리합니다. 상단 범례, 차트 내부 데이터 표와 아래 가로형 원천 표를 포함합니다.

원본처럼 종합은 전년 동월부터 당월까지 13개월, 거래처 그래프는 최근 12개월을 표시하고 3·6·12개월 평균을 추가합니다. 각 그래프의 아래 표는 평균 계산에 필요한 13개월을 모두 보존합니다. 이동 평균은 당월 제외, 전년도 평균 선은 직전 달력 연도 12개월의 실제 마감 평균입니다. 확인되지 않은 월은 0으로 보정하지 않으며 해당 평균도 비웁니다. 차트의 값·캐시는 같은 동결 누적 자료에서 생성하고 원본 파일의 과거 차트 캐시를 복사하지 않습니다. 계산서 왼쪽 품목표와 확정 수량·금액은 유지합니다.

검증은 저장 후 혼합 그래프 구조·색상·이중 축·월 범위·데이터 표·미확인 점의 누락·원 단위 보존을 검사하고, 실제 9월 파일의 종합·화성·광명 그래프를 렌더링하여 확인합니다. 출력 파일은 시험 확정 v3의 연습 조정값을 포함합니다. 원본 자료는 수정하지 않으며 틀 고정도 추가하지 않습니다.

## 꺾은선 및 축 방향 정정 — 양식 v5

사용자 캡처와 다시 대조하여 직선 꺾은선을 명시적으로 설정했습니다. 금액은 왼쪽 축(천원 표시), 수량은 오른쪽 축(개)으로 배치하고 Excel에서 축 숫자가 표시되도록 tickLblPos를 명시합니다. 차트·계열 모두 smooth=false이며 전년도 평균은 점선을 유지합니다. 데이터 표는 기간이 가로, 여섯 계열이 세로인 Excel 기본 데이터 표입니다. 회색 격자와 표의 글꼴도 명시했습니다.

이전 미리보기 도구는 곡선·축 위치·데이터 표 방향을 Excel과 다르게 표시했습니다. 따라서 양식 일치에 대한 기존 설명은 부정확했습니다. 이번 검증에는 설치된 Microsoft Excel에서 생성 파일을 읽기 전용으로 열고 종합·화성·광명 차트를 직접 PNG로 내보내는 절차를 추가했습니다. 원본이나 확정 수치는 변경하지 않았습니다. 관련 보고서 테스트 12개 통과.

원본 자체에도 그래프 참조값과 누적값 차이가 있습니다. 기아 광명 T35(2026년 6월 실적 금액)는 4,103,799원이지만 같은 파일의 종합3(누적)은 4,103,799,242원입니다. 기존 출력은 동결한 누적값을 사용하므로 첨부 캡처의 6월 급락까지 복제하지 않습니다. 수치 근거가 다른 경우 모양을 맞추려고 값을 변경하지 않습니다.

## 출력표 간 자동 검산 보완

`backend/adapters/export_validation.py`에서 저장된 XLSX를 확정본과 대조한 다음에만 출력 파일을 등록합니다. 이전 검산은 전체 금액과 계산서 전체 수량을 확인했지만, 이제 품번·촉매사·마감처별로 ERP와 각 계산서를 대조하고 상세 공장별 자동·적용 수량 및 금액을 확인합니다. 희성 가로표의 공장 열별 수량, 희성·유미코아 상세 명세, 미마감의 전월·추가·해소·잔여·금액, 수량 검산표와 종합표도 대조합니다. 계산서·희성표·미마감·종합의 합계행을 함께 검증합니다.

양쪽 거래처의 오류가 상쇄되어 전체 합계만 맞는 경우에도 출력은 실패하며 오류가 있는 표와 항목을 알립니다. 검증 실패 시 임시 XLSX를 제거하고 출력 이력이나 최종 파일을 등록하지 않습니다. 저장된 원본·사용자 조정·기존 확정본은 변경하지 않습니다.

보고서 및 9월 회귀 19개, 잘못된 출력값을 주입하는 검증 9개를 통과했습니다. 실제 시험 저장소의 기존 세 확정 버전을 모두 다시 출력하여 대조했습니다. 상세 수치·파일 해시와 대조 결과는 저장소 밖의 개인 작업 폴더에 보관합니다. 이 검산은 출력이 확정본과 일치하는지 확인하는 절차이며, 사용자 미승인 값이나 과거 원본 간 차이를 자동으로 승인하는 절차가 아닙니다.
