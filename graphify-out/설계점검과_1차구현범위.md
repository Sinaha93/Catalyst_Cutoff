# 촉매 마감 설계 점검과 1차 구현 범위

2026-10-13 · 설계 검토안

첫 구현의 목표는 **한 달의 자료를 가져와 기본 계산과 필요한 예외 처리를 거친 뒤, 확정 이력과 엑셀까지 남기는 것**입니다. 특정 시범 품번만 지원하는 기능으로 제한하지 않습니다. 등록된 전체 품목·경로에 같은 구조를 적용하고, 근거가 부족한 명세는 미완료로 표시합니다. 프로그램 구현과 최종 UI 채택은 아직 시작하지 않았습니다.

## 이번 점검 범위

Graphify로 저장소의 README와 설계·검토 문서 3개를 분석했습니다. 입력 문서와 해시는 `source-snapshot.json`, 관계의 출처와 확실성은 `graph.json`, 구조 분석 결과는 `GRAPH_REPORT.md`에 남겼습니다. 이 보고서는 그 연결과 원문을 검토해 정리한 개발 범위 제안입니다. 아래 수량은 문서에 기록된 기존 대조 결과이며 이번 작업에서 업무 엑셀을 다시 계산한 값이 아닙니다.

문서 4개에 설계의 네 축인 경로, 계산, 월별 입력·검토, 이력·출력이 모두 있습니다. 남은 일을 구분하는 것이 필요합니다. **업무 규칙의 설계, 개별 원본 차이의 해소, 프로그램 구현, 실제 동작 검증은 서로 다른 완료 상태**입니다.

## 연결 점검에서 중요한 사항

| 연결 | 현재 근거 | 첫 구현에 반영할 내용 |
|---|---|---|
| 원본 → 경로 → 비율 | 운영 설계 14절, 상세 설계 5.2 | 집계할 수불 열과 경유 후 중복 이동을 구분합니다. 제품×BOM 근거를 촉매·세부 공장별로 합산합니다. |
| 원천 총량 → 보류·해소 → 배분 대상 | 운영 설계 21절 | 촉매사 이월+납품과 우리 미정산+ERP를 따로 대조합니다. 서로 다른 출처의 일부 숫자를 섞지 않습니다. |
| 실제 입고 → 글로비스·직사급 | 운영 설계 15·18·21절 | 실제 입고×BOM을 적용하되 28991-4C520은 전주 귀속을 유지합니다. 대여270을 제품 입고100으로 해소하지 않습니다. |
| 기본 비율 → 월별 수정 → 검산 | 운영 설계 20.3·22.3 | 자동값·수정값·사유를 구분합니다. 빈칸과0을 구분하고 다른 공장의 수량을 몰래 변경하지 않습니다. |
| 미완료 → 확정 조건 | 운영 설계 22.4~22.5 | 필수 근거 누락은 해결해야 하지만, 근거 있는 미정산은 잔여와 함께 확정할 수 있습니다. 필터로 숨겨진 미완료도 검사합니다. |
| 확정 명세 → 모든 출력·다음 달 | 운영 설계 17·18절 | 출력별로 다시 배분하지 않습니다. 동일 확정 명세를 집계하고 당시 원본·기준·입력·이월 연결을 함께 보존합니다. |

## 문서를 읽을 때 혼동할 수 있는 부분

새로운 업무 오류로 단정하지 않고, 이전 기록과 후속 설계를 구분합니다.

| 이전 표현 | 현재 읽어야 할 기준 | 처리 |
|---|---|---|
| 상세 설계6.1의9번은 글로비스 처리 순서를 추후 확정한다고 설명 | 같은 절 첫 문단과 운영 설계21.4에 후속 계산 순서가 있음 | 계산 순서는21.4를 적용합니다. 원천 전표 차이까지 해결됐다는 뜻은 아닙니다. |
| 운영 설계18.5는 전체 품목 출력 확대를 남은 일로 기록 | 19절에서9월 확정 명세114행·97촉매로 대조 확대 | 확정 명세 전수 대조는 진행됐고, 원본부터 전체 자동 배분을 재현한 검증은 남아 있습니다. |
| 기존 화면 시안의 글로비스 전체 잔여449 | 18.2와22.6은 미입고449+전월 잔여1=전체450 | 첫 화면 구현의 기대값은450입니다. 이번에는 기존 시안 파일을 수정하지 않습니다. |
| 운영 설계20.6의 Graphify 미설치 기록 | 이후 설치 및 이번 실행 | 당시 기록은 유지하고 이번 실행 결과와 입력 스냅샷을 별도로 남깁니다. |

## 1차 구현에 포함할 범위

| 순서 | 만들 기능 | 완료 기준 |
|---|---|---|
| 1 | 월 작업·원본 등록·기준 버전·초안 저장 | 자료 역할·기간·해시·원본 위치를 남기고 중복 등록과 수정본을 구분합니다. 종료 후 입력·빈칸·0·작업 상태가 복원됩니다. |
| 2 | 현재 확보 양식 읽기와 전체 대상 분류 | ERP·제품/반제품 수불·희성·유미코아·글로비스를 각각 읽습니다. 거래·이월·BOM·경로로 대상을 연결하고 단산·계획 없음만으로 실제 거래를 삭제하지 않습니다. |
| 3 | 총량 정합과 경로별 계산 | 원천 대조, 보류·해소, 글로비스·직사급, 일반 비율, 정수 반올림, 단가·금액 순서로 처리합니다. 유미코아 기구분 명세에 희성 배분을 일괄 재적용하지 않습니다. |
| 4 | 월별 입력과 필요한 항목 처리 | 제품 공장별 분할, 촉매 최종 수량 수정, 원천 차이·보류 처리를 서로 다른 입력으로 제공합니다. 근거가 없는 항목만 구체적인 처리 목록에 올립니다. |
| 5 | 확정·재확정·이월·백업 | 입력 변경 후 재계산 필요 표시, 부분 저장 방지, 중복 확정 방지, 이전 확정본 보존, 다음 달 영향 표시, 별도 위치 복구 검증을 지원합니다. |
| 6 | 동일 확정 명세의 엑셀 출력 | 희성 마감표, 현대기아 세부 공장 검토표, ERP 지역 명세, 미정산표를 같은 확정본으로 생성합니다. 출력 실패 후 같은 버전으로 다시 만들 수 있습니다. |

순서는 개발 의존관계이며 모든 화면을 마지막에 붙인다는 뜻은 아닙니다. 1단계부터 작업 흐름을 확인할 수 있는 화면을 만들고 각 단계에서 가독성과 입력 동작을 검토합니다. 현재 UI 시안의 색상·배치·기술을 그대로 확정하지 않습니다.

원본 읽기, 기준 관리, 계산, 저장, 출력, 화면은 역할을 나눕니다. 로컬1인 프로그램이라는 방향을 유지하고 실제 기술·DB 구조·모듈별 구현 계획은 코드 착수 전에 구체화합니다. Graphify는 설계·코드 점검 도구로 사용하며 월마감 계산의 필수 실행 의존성으로 넣지 않습니다.

## 뒤로 미룰 기능과 남겨야 할 처리

| 뒤로 미룰 내용 | 1차에서 유지할 동작 |
|---|---|
| 현대기아·ERP 자동 업로드/자동 등록 | 세부 공장·ERP 지역 검토 엑셀을 제공합니다. 등록 규격이 확인되기 전에는 업로드용이라고 표시하지 않습니다. |
| 새로운 양식의 AI 자동 해석과 외부 API 연결 | 현재 확인된 양식은 결정된 규칙으로 읽고, 양식 변경은 감지해 열 연결 보완이 필요함을 표시합니다. |
| 미확정 완성차 직납·서열-전주(HSL)의 자동 경로 결정 | 해당 월 거래가 있으면 누락하지 않고 필요한 근거와 영향 범위를 표시합니다. 근거 없는 귀속을 추정하지 않습니다. |
| 과거 전월 전체 자동 재계산·완전 자동 이관 | 확인된 과거 확정값과 출처를 이관하고 미확인 기간은 표시합니다. 새 달 계산 검증과 구분합니다. |
| 고급 대시보드·계획 재산출·누적 보고서 고도화 | 월별 확정 명세와 계획 버전을 보관해 이후 확장할 수 있게 합니다. 계획 미수령을0이나0%로 표시하지 않습니다. |

월별 예외·이력·기본 백업·재확정은 편의 기능으로 미루지 않습니다. 미확정 경로의 자동 결정은 보류하더라도 미확정 상태를 표시하고 해당 월 확정을 제한하는 기능은 포함합니다.

## 검증 순서와 통과 기준

1. **현재 자료를 읽는 검증:** 원본 시트·행·셀과 추출 결과를 대조합니다. 현재 양식 전체 행의 포함/제외 사유를 확인합니다. 같은 파일 재등록과 수정본 교체도 검사합니다.
2. **대표 예외를 사용하는 계산 검증:** UCC 경유 중복 제외, 공유 촉매, 반제품, 글로비스, 전주 직사급,2J540 분할, 빈칸/0, 월별 수정 합계, 반올림을 먼저 확인합니다. 대표 사례는 검증 시작점이며 지원 대상을 이 사례로 제한하지 않습니다.
3. **9월 전체 범위 대조:** 확정97촉매·114명세, 미정산61행과 연결합니다. 원천154촉매는 별도 대상 분류로 관리합니다. 과거 확정값을 넣은 검산과 새 계산 결과를 명확히 구분합니다.
4. **차이의 분류:** 과거 배분 비율 차이는 그대로 비교 정보로 남깁니다. 새 월의 총량·귀속·입력 누락은 해결하거나 근거 있는 보류로 연결해야 합니다. 과거 결과를 맞추기 위해 임의 비율을 고정하거나 자동 수정값을 만들지 않습니다.
5. **저장·출력·복구 검증:** 같은 확정본에서 출력 합계가 일치하는지, 재계산이 과거 확정값을 바꾸지 않는지, 전월 변경 영향과 출력 실패·재실행·복구가 올바르게 처리되는지 확인합니다.

기존 문서의 대조 기준은 마감151,090개·19,870,764,335원, 미정산20,874개, 글로비스 마감18,538개·전체 잔여450개입니다. 이는 이관·출력 대조 기준이며 현재 수불로 계산한 모든 공장별 후보가 반드시 과거 배분과 같아야 한다는 조건이 아닙니다.

## Graphify 실행 결과와 해석 범위

- 문서4개·약25,669단어에서 주요 항목56개·연결82개·그룹7개를 추출했습니다. 원문에 명시된 연결만 포함했으며 EXTRACTED 표시는 문서 근거가 있다는 의미입니다. 실제 프로그램이나 업무 수량의 검증 완료를 뜻하지 않습니다.
- 연결 양끝 누락, 자기 연결, 같은 노드 쌍의 중복으로 인한 연결 손실은 모두0건입니다. 입력 문서4개의 해시가 실행 전후 동일함을 확인했습니다.
- 원본 등록·수정본·출처 추적11개, 월 확정본과 근거 스냅샷9개, 제품별 다중 경로8개, 기본 비율 배분7개 연결이 있습니다. 이 때문에 원본·버전·경로·확정 명세를 별도 책임으로 설계하는 것이 중요합니다.
- 자동 보고서의 낮은 연결 수는 이번 추출의 선택 범위에도 영향을 받습니다. ERP 마감처나 초안 저장 등의 연결 수가 적다는 이유로 업무 설계 누락이라고 단정하지 않습니다. 원문22절에 실제 규격이 있습니다.
- 기본 벤치마크는 질의 어휘가 맞지 않아 결과를 내지 못했습니다. 실제 그래프의 한국어 용어로 구성한4개 질의로 다시 측정한 도구 추정치는 원문 약34,225토큰·평균 조회 약2,768토큰·조회당12.4배 감소입니다. 추출 비용을 포함한 실제 절감률이나 답변 정확도의 측정값이 아닙니다. 호스트의 실제 입력·출력 토큰 사용량은 제공되지 않아 비용은 미측정으로 남겼습니다.
- 그룹 응집도는0.2424·0.2182·0.2500·0.2857·0.4667·0.4000·0.5000입니다. 이 수치는 추출 그래프의 연결 밀도이며 설계 완성도나 정확도 점수가 아닙니다.
- `graph.html`은 대화형 관계도이며 시각화 라이브러리를 CDN에서 불러옵니다. 오프라인에서 보장되는 조회 결과는 `graph.json`, `GRAPH_REPORT.md`, `query-history.txt`, `query-glovis.txt`입니다.
- 결과는 저장소의 `graphify-out/`에 생성되어 Git 변경 목록에 나타납니다. 업무 문서에서 추출한 내용이므로 공유 범위를 확인한 후 필요한 결과만 관리합니다. 이번에 커밋하거나 원격 저장소로 전송하지 않았습니다.

## 다음 작업

이 범위를 기준으로 **저장 구조, 계산 모듈의 입출력, 화면과 계산의 연결, 구현 작업별 인수 기준**을 구체화합니다. 실제 개발을 시작할 때는 가장 작은 정상 계산 사례와 예외 사례로 한 달의 흐름을 먼저 연결한 뒤 같은 구조로 전체 품목을 검증합니다. 남아 있는 원천 차이·세부 경로는 사용자에게 전부 재검토를 요청하지 않고, 자료로 해결할 수 있는 부분을 먼저 대조합니다.
